What changed from today
  • Same ten sections as the app has now (TypeSettingsPage.tsx), redrawn in the Settings style: a section list on the left, one label column, one control column, notes under the control.
  • Card (new) replaces Preview properties: Title is always shown and the user picks any properties to add, in order (no limit of 4, no part switches). Each property is drawn by its kind. Embeds’ Card mode uses it.
  • Views (changed) lists the type’s saved views instead of the disabled Add view / Edit buttons; it matches the tabs on the type page.
  • Properties: one property open at a time (Status shown: type, Required, default, options with colour and state). Templates stays disabled until v1.0.
  • The Tag type keeps its own rules: no Properties, Card or Hidden sections (D-693, D-728).
To decide
  1. Card replacing Preview properties extends FR-TYP-11. Record as a decision?
  2. Should the type page’s Columns (FR-TYP-09) also be listed here, or stay only on the type page?

Rules this shows
• A picked property with no value (here Due, Stakeholders) or the placeholder “—” (Board Rank) is left out; nothing is drawn for it.
• Source holding a Jira URL shows as a link chip with the issue key; a file:// folder shows as ↗ with the folder name.
• Emoji in a text value (🟡) is kept as written.
• The body’s start is the first plain text after the headings, so here it is “Jira: IDCTP-18…” and the generated Next step line; C3 and C4 show the Business problem text instead.

E · Searching icons
The same picker opens from a property’s icon button and from the type’s Icon in General. The picker holds the whole Lucide set (1,539 icons, ISC licence). The picker shows no counts. Typing filters it as you type: it matches icon names and their Lucide keywords, so “health”, “pulse” or “heart” all find heart-pulse. Each result shows its name under it, with the typed part in bold.
