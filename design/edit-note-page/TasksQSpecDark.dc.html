Schedule and Kanban as views

The Tasks page becomes a type page with views, like every other type. Schedule and Kanban are saved queries shown as boards; the full-window boards beside this one show them in the app.

  • A board with horizontal lanes grouped by Due · by period, a new grouping for date attributes: Today & overdue, This week (one heading per day), Later, Not scheduled.
  • Done in its own lane replaces Schedule’s fixed Done section (D-378): last 7 days, collapsed. The grouping attribute (Due) still shows on cards here, because a period lane doesn’t give the exact date.
  • Everything else is the view from the Views page: tabs, sort button, lanes switch, the same task card.

  • A board with vertical lanes grouped by Status: To do · In progress · Waiting · Done. Done keeps only the last 7 days through the filter group; Cancelled is filtered out (D-378).
  • Cards hide the Status pill (the column says it, D1 rule on the Views page). Dragging a card to another column writes the status.
  • Lanes can be reordered in both views: drag a column (Kanban) or a row (Schedule) by the grip on its header (shown on In progress and Later). The order is saved in the view as lane_order.
  • No “Show more”: each lane shows all its tasks and the page scrolls down. Columns are 300 px wide; when they don’t fit the window the board scrolls sideways (Done is cut at the right edge, with the scrollbar under the board).
  • The Kanban’s “columns by tag” (D-378) becomes simply Group by: Tags; a task with two tags shows in both columns with both tags on the card.
C · Files
.tegg/queries/Schedule.yml
title: Schedule
types: [task]
filters:
  - status: { is_not: Cancelled }
view: board
group_by: { due: period }
lanes: horizontal
done_lane: { within_days: 7, folded: true }
sort: [ { by: due, order: asc }, { by: priority, order: desc } ]
columns: [tags, body, due, priority, source]
.tegg/queries/Kanban.yml
title: Kanban
types: [task]
match: all
filters:
  - status: { is_not: Cancelled }
  - group:
      match: any
      filters:
        - status: { is_not: Done }
        - completed: { within_last_days: 7 }
view: board
group_by: status
lanes: vertical
lane_order: [To do, In progress, Waiting, Done]
columns: [tags, due, priority, source]
.tegg/types/task.yml
name: Task
views: [Schedule, Kanban, All tasks, Waiting on others]
# Schedule first = opens first; All tasks is the type page table
  • Schedule and Kanban become ordinary saved queries: editable, duplicable, usable as blocks in notes (FR-TSK-04’s “each is a saved query”, D-379).
  • New keys (green): group_by: { due: period } and done_lane. A new vault gets both files; deleting one removes the tab, and Restore default views in Type settings brings them back.
What the BRD says
  • FR-TSK-04: Schedule (Today & overdue, This week, Later, Not scheduled, Done collapsed) and Kanban; “each is a saved query that the user can edit or duplicate (FR-QRY, v1.0)”.
  • FR-TSK-05: board by status or any select attribute; drag changes the attribute. D-378: the two views as built in 5A; D-516/D-517: one Tasks page with Schedule, Kanban and All tasks, its header and Task views tablist.
  • Reuses the Views page: view tabs, sort button, Vertical | Horizontal lanes, the grouping-attribute rule, query files (R138).
  • All tasks and names are invented (D-62).
