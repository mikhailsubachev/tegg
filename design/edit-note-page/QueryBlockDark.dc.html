Embedded query block

A query as a block inside any note: pick types, filter by attributes and by links to the current note, and see a live list. The block can show its results as a list or as a table with chosen columns.

A · Query block in a note (list view)

FR-QRY-06 · in the note body, like any other block
Meeting · Tue 7 Oct 2026

2026-10-07 Weekly Sync

Agenda: Q4 budget status, offsite logistics. Finance wants the draft before Friday; Lisbon Offsite 2026 needs a venue this week.

Follow-ups

Next sync: Tue 14 Oct.

  • The block shows only its title, the result count, the view switch and the results. The filters are not repeated in the block; they are shown when the query is edited (B). Results update live when files change (FR-QRY-09).
  • “This note” is context-aware (FR-QRY-03): the same block in a template finds the tasks of whichever note it lands in.
  • Each row is the object’s link chip exactly as in the Backlinks panel (Link chip variants, D-368): stacked chips, long titles wrap: type icon and title, and for a task the due date and status after a divider. Click previews, double-click opens (FR-LNK-08).
  • List or Table is chosen in the editor (B, View); the block itself has no view switch. List is the default.

E · Stored in the Markdown file

FR-FMT-06
```query
title: Open tasks from this meeting
types: [task]
match: all            # top level: all = and, any = or
filters:
  - links_to: this
  - status: { is_not: Done }
  - group:              # second level, its own connector
      match: any
      filters:
        - due: { within_next_days: 14 }
        - priority: High
sort: { by: due, order: asc }
limit: 50
view: list
columns: [status, due]   # used by the Table view
```
  • A fenced query block with readable YAML (FR-FMT-06). Other tools show it as a code block; nothing is lost.
  • this means the note that contains the block. “View source” in the editor shows and edits this text.
  • The key names are a proposal for the file format.

  • Show: one or more object types; leaving it empty searches all types (FR-QRY-01).
  • Filters: attribute + operator + value. Attributes are grouped: Links, the attributes every object has, then the chosen type’s own attributes. With several types, only shared attributes are offered.
  • and / or, two levels: the connector on the second row is a menu (and, or) and applies to every row at that level; the rows below repeat it in grey. Add group makes a box with its own connector, e.g. Status is not Done and (Due within 14 days or Priority is High). Groups cannot hold groups.
  • Links to · This note is the context-aware filter; the value can also be any picked object, e.g. [[Q4 Budget]].
  • Opens from the pencil in the block header or ⌘↩ on a selected block. Changes apply live; Esc closes.

D · States

Empty, broken filter, many results
  • No results: one muted line and Edit query; the block keeps its size small.
  • A filter on a missing attribute or type is ignored, never silently dropped from the file; the block says so in one line, and the filter is marked in red in the editor.
  • Mixed types: each row is just that object’s chip with its own type icon, nothing next to it; long results show the limit, then “Show 50 more”.

  • Table is the second view in this version; Cards are dropped. The view is chosen in the editor (B); the block header has no switch.
  • In Table view the block header has a Columns button next to Edit; it opens the app’s Columns list from type pages (D-252, D-260): the type’s attributes in schema order, then Tags, Source, Aliases, Created, each with a check; then New property…, exactly the app’s menu. Title is listed first, always checked and read-only (it is always the first column); Modified is always the last column and is not listed. Up to 4 can be checked; the rest are then disabled (“Up to 4 columns”). The button appears only in Table view.
  • With all types or several types, the table switches to the mixed view (G): system columns only.
  • The choice is saved in the block (a columns: line in the query YAML), not in the type’s preview, so each query has its own columns. Order follows the list.
  • A click on a column header sorts by it, the same as Sort in the editor. Cells are read-only in this version; editable cells (FR-QRY-05) come later.

Mixed types: only columns every object has.
  • When Show has no type (all types) or more than one type, the table is the mixed view: each row starts with its own type icon, and there are no type-specific columns.
  • The Columns menu then offers only system columns: Title (always first, checked, read-only), Type, Tags, Source, Aliases, Created. Modified stays the fixed last column. No New property…, since a property belongs to one type.
  • Type is new here: a text column with the type name, useful only when types are mixed. It is on by default in the mixed view.
  • If a query goes from one type to several, columns the types do not share are dropped from the block; the columns: line keeps only system columns.
