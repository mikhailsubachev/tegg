Views on a type page

A view is a saved query shown as a tab on its type’s page. It uses the query file, editor and rules that already exist; the type file only lists which queries are its tabs.

  • All books is the type page as it is today (FR-TYP-09: every book, columns from the type file). It is always first and can’t be removed.
  • Every other tab is a saved query shown on this page: same filters, sort, view and columns as in a note’s query block, with the type fixed to Book.
  • No filter summary on the page: the tab name says what the view is. Edit view (in the tab’s ▾ menu, E) opens the query editor (C) with the filters. The text filter and Columns work as on the type page; Columns writes the view’s columns.
  • Column widths: drag a header’s right edge (shown on Title). Widths are kept per view, on this Mac, as on the type page (FR-TYP-09); they are not written to the query file.
  • Sorting is set on the view by the user. The sort button opens the list shown: any number of levels (Finished, then Rating, then Title), each with its order, reordered by dragging. The button reads the first level and +2 for the rest; headers show ¹ ² for the levels.
  • A header click makes that column the only sort; ⇧-click adds it as the next level (or flips its order). Every change writes the view’s sort once (as D-1444), so the view opens sorted the same way everywhere.

Exception for attributes with several values (multi-select, tags, relations): when grouped by such an attribute, a card that has only the lane’s value shows nothing extra, and a card with several values appears in each of its lanes and shows all its values on the card, so you can see where else it is.

One definition, two references
.tegg/types/book.yml (the type file)
name: Book
folder: Books
columns: [author, rating, status, modified]
views: [Reading, Read in 2026, Favourite authors]
# the tab order; each name is a saved query
.tegg/queries/Reading.yml (R138, unchanged format)
version: 1
title: Reading
types: [book]
match: all
filters:
  - status: { is_any_of: [Reading, To read] }
  - tags: { has_none_of: [odloženo] }
sort:
  - { by: status, order: asc }
  - { by: modified, order: desc }
view: wall
group_by: status
lanes: columns
lane_order: [Reading, To read, Read]
# no columns: a wall draws the Book card (book.yml › card)
  • The definition is an ordinary saved query (R138). The type file only lists which queries are its tabs, in order.
  • view: wall is new; view: board (kept when written by hand, D-1438) reads as a grouped wall. group_by is already kept when written by hand (D-1438); Q2 makes them valid. A missing lanes reads as columns; it is ignored when there is no group_by. sort may now be a list (one level per item); the single-mapping form of R138 still reads as one level. A query whose types no longer is exactly [book] stays listed with a broken notice instead of disappearing.
What the BRD says
  • FR-QRY-07 (M): each type has default views (FR-TYP-09); users can add more views per type, e.g. Books: “Currently reading” board, “Read in 2026” table.
  • FR-QRY-05: Table, List, Board (group by select), Calendar (by any date attribute). Owner, 2026-11-19: no Calendar view; views are Table, List and Board. FR-QRY-08: new objects from a view are pre-filled.
  • D-1438: slice Q built List and Table; slice Q2 (v1.0) adds group by, Board, Calendar, editable cells, FR-QRY-04 and FR-QRY-07. This board is Q2’s design.
  • Owner, 2026-11-23: grouping in every view, a display switch (List · Table · Wall) on every view and on every query block, and Wall as the one cards display: no separate Board or Kanban, a board is a Wall grouped by something, with lanes as columns or rows. FR-QRY-05 names Board (group by select) and has no Wall (its “Gallery/cards: S” comes closest).
  • Reused unchanged: R138 query files, the editor (R142), D-1433…D-1446 (names, renames, trash, sort click writes, shared edits).
  • Sorting (owner, 2026-11-17): set on the view by the user (sort button or header click), saved in the view; not in the editor.
  • All names and books on this board are invented (D-62).
