G · Shared behaviour of every 4E job

Plan, then confirmThe dialog shows the counts the core planned: files, links, names that get a suffix. Cancel leaves the vault byte-identical.
Backup firstMulti-file jobs make the backup zip (D-57) before the first write; it is listed in Settings › Backups. A single-file type move does not.
Only the affected filesEach file is rewritten by a text edit of its own lines; bytes outside them stay. Files changed by another app meanwhile are skipped and listed.
Progress, not a modalThe status strip of 4C: count, Cancel while planning, then Undo for 5 s and in the palette. An open note gets its edits as one undo step in the editor.
Not updated listSkipped files show title, path and reason with Open, Retry and Retry all, as for links after a rename.
Never on system typesDaily Note, Tag, Image and PDF are neither targets nor sources of a type move; their built-in keys cannot be renamed or removed.
