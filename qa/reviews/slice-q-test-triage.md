# Slice Q: triage of the failing tests after the build (HEAD c3dcbd2)

Independent triage of the tests reported failing after the slice Q build (saved queries, FR-QRY-01…09). Each test was read
against the decisions (BRD D-1433…D-1504 and the older ones they rest on), the ACs (`docs/acceptance/queries.md`,
`pinned.md`, `embeds.md`, `date-picker.md`), the contracts (`docs/contracts/v1-queries.md`, `v1-pinned.md`,
`ms3-shell.md`), the dialect (`docs/markdown-dialect.md`) and the fixtures, then run. Product and fake code wasn't read
or changed.

**Every edit to an AC test file below changes an existing AC test (TS-I3).** The commit needs the trailer
`AC-Test-Change: <reason>; approved-by: owner` and the owner's approval. The fixture edit
(`tests/fixtures/vaults/queries/.tegg/types/schůzka.yml` plus its README line) needs the same approval.

Counts: 30 failing tests triaged. **28 test wrong** (one also needed a fixture fix), **2 product wrong**, 0 fake wrong,
0 flaky-env. `app/webkit/helpers.ts`'s uncommitted `READ_COMMANDS` change is **correct** (see the end).

## Product and fake bugs (for the implementer)

- **P1, product (FR-TPL-04 AC-1, FR-QRY-09; contract §2.3).** Case: a note is created from a template (⌘N › Schůzka › title ⏎) and its query block is drawn (`No objects match.`). A `vault:changed` + `query:stale { types: ['task'] }` for a new task then triggers no `query_run` from that block until the note is reopened. Expected: §2.3 (b) re-runs the block (debounced 300 ms) because `task` is one of the query's `types`, and it lists `Tasks/Úkol nové porady.md` within 1 s. The note isn't being typed in, so the "waits for that note's autosave" rule must not hold the re-run indefinitely after the draft → note transition (D-521, D-522). Test: `queries_block` `fr_tpl_04_ac1_template_block_uses_the_new_note`.
- **P2, product (`packages/editor`, FR-EDT-02 AC-24).** Case: a top-level query block is selected (NodeSelection) and the block directly above it is another query block. ↑ doesn't move the NodeSelection to that block; the selection stays where it was. Expected: ↑ selects the previous atom block as a whole, and ↓ the next one, the same way ↑ from a paragraph start selects the block above. Test: `queries_block` `fr_edt_02_ac24_query_block_is_one_atom` (Porada 7: ↑ ↑ from `Další porada:` then ⇧⌘↓ must put `Úkoly z této schůzky` before `Otevřené úkoly z této schůzky`).
- **P3, product (date picker, date-picker.md R89 keyboard; FR-TYP-02; possibly T1).** Case: the `Pick date` dialog is open from a task's `Due date` with the focus on a day button, and a printable key is pressed. The focus jumps to `Note body` and the characters are typed into the note while the dialog stays open. Observed: T4's body became `2026-11-20\n\nBez termínu.` and the file was saved. Expected: keys pressed inside the dialog stay in the dialog (arrows, ⏎, Space, Esc, Tab per R89; a printable key either does nothing or goes to the `Date` field), and the note is never edited. This isn't a slice Q test failure; it needs a regression test `bug_<issue>_fr_typ_02_…`.
- **P4, product (minor, FR-UX-03 AC-42 / R144).** ⌘↩ right after `Insert query` › choose (before the new block has drawn its first rows) is ignored even though the block is already selected in the focused editor. Expected: ⌘↩ on a selected query block opens its editor in any state. The test now waits for the rows, so this doesn't fail a gate.
- Fakes: no fake bug found. `fake-pins` (D-1501) and `fake-queries` / `fake-core` (`query:stale`, dialect §6 link resolution) behaved as specified in every case checked.

## `app/webkit/helpers.ts` (uncommitted)

Adding `queries_list`, `query_get`, `query_run`, `query_usages` to `READ_COMMANDS` is **correct**. Contract §2's table marks
`queries_list`, `query_get` and `query_run` "Read-only", and `query_usages` is a lookup (`Core::query_usages`: index plus a
template scan, no write). Every writing command (`query_apply`, `_revert`, `_create`, `_duplicate`, `_rename`, `_trash`,
`_restore`) stays out of the list.
