**Risk tiers** (test-strategy §3). This slice **writes vault files**: the query files `.tegg/queries/*.yml`, the notes that get or lose a block, `.tegg/pinned.yml`, and (through the rename job) every note and pin that refers to a query. So its top risk is **T1, data loss**: an external or synced change to a query file overwritten; an unreadable query file rewritten; comments or unknown keys dropped; a note's bytes changed when a block is only shown, run or edited; a block or pin removed when its query is renamed, trashed or missing. Those criteria are marked **(T1)** and check bytes. Next is **T2, silently wrong data**, here the biggest surface: **query results** (test-strategy lists them under T2). Wrong `this` context, date operators shifted by a time zone, NFC/NFD names, Czech collation, case and diacritics in comparisons, trashed or template objects in results, an ignored filter widening results without saying so. Those criteria are marked **(T2)** and are checked against a brute-force oracle as well as fixed expectations.

### R138. `.tegg/queries/<name>.yml` (FR-QRY-06, FR-STO-06; AP-1290, AP-1291, AP-1293)

**Format** (`Otevřené úkoly z této schůzky.yml`; key names from board E, "a proposal for the file format"; versioned like `.tegg/types/*.yml` and `.tegg/graph.yml`, AR-07):

```yaml
# Tegg saved query (FR-QRY-06). Edit it in Tegg: Queries › Otevřené úkoly z této schůzky.
version: 1
title: Otevřené úkoly z této schůzky
types: [task]
match: all
filters:
  - links_to: this
  - status: { is_not: Done }
  - group:
      match: any
      filters:
        - due: { within_next_days: 14 }
        - priority: High
sort: { by: due, order: asc }
limit: 50
view: list
columns: [status, due]
created: 2026-10-19T09:00:00+02:00
modified: 2026-11-02T14:30:00+01:00
```

| Key | Rule |
| --- | --- |
| `version` | a positive integer; missing reads as 1; 1 is current; > 1 → **read-only** (runs, can't be edited); `0`, a string or a fraction → **unreadable** |
| `title` | the display title (user content, NFC). Missing or blank → the name (file stem). Tegg keeps the file stem equal to the sanitized title (FR-FMT-08, D-52, AP-11, ≤ 200 UTF-8 bytes; AP-1291) |
| `types` | a list of type keys; missing or `[]` = all types (board B "none = all types"). A key with no definition and no objects is a **broken** part (R141) |
| `match` | `all` (and) or `any` (or) for the top level; missing = `all` |
| `filters` | a list of filter items (R139); missing = no filters |
| `group` item | `{ match, filters }` with its own connector; a `group` inside a group is **broken** and ignored (board B "Groups cannot hold groups") |
| `sort` | `{ by: <attribute key, title, created or modified>, order: asc \| desc }`; missing = `{ by: modified, order: desc }` (the type page's default, D-233). Ties: title (D-122 collation), then path. Empty values sort last in both orders. Select values sort by option order, unknown values after the last option (D-477) |
| `limit` | a positive integer, the page size of AP-1300; missing = 50 |
| `view` | `list` or `table`; missing = `list` (board A "List is the default") |
| `columns` | a list of column keys for `table` (R130's keys plus `type`, AP-1294); missing = the R130 effective columns of the single type, or `[type, modified]` when mixed (board G "Type … on by default"; Modified shown by default as on the boards) |
| `created`, `modified` | ISO 8601 with offset (FR-FMT-11), written by Tegg: `created` on create, `modified` on every commit that changes another key (never on a no-op, AP-5) |
| anything else | top-level keys, per-item keys and every comment are kept byte for byte (FR-FMT-07) |

**Read rules.** UTF-8 YAML. Invalid YAML, invalid UTF-8, a top level that isn't a mapping, or a bad `version` make the file **unreadable** (listed with its name, state `Can't be read (line <n>)`, never rewritten, AP-1299). A bad value of any other known key (e.g. `limit: many`, `view: board`, `match: some`, `types: task`) is a **broken part**: its default applies, the block and the query page say which key, and the file is not rewritten. Only `.tegg/queries/*.yml` directly in that folder are queries; sync conflict copies (`<name> 2.yml`, `<name> (conflicted copy …).yml`) are listed like any other file (they **are** queries with their own names, AP-1291) but never written by Tegg except by the user's own actions on them.

**Write rules** (AP-1293). One atomic write per user action (FR-SYN-02), with the version last read as base (FR-SYN-03).

- **Commit of the editor** replaces only the lines of the top-level keys whose value changed (from the key's line to the line before the next top-level key or trailing comment block), re-emitted in the style above (flow for `types`, `sort`, `columns`; block list for `filters`); a trailing comment on a replaced single-line key is kept; every other line stays byte for byte; `modified` is set to the commit time.
- **Create** (New query, `/query` › `New query`, `Save as query…`): the header comment, then `version`, `title`, `types`, `match`, `filters`, `sort`, `limit`, `view`, `columns`, `created`, `modified` in that order, keys at their defaults written explicitly. Created exclusively: an existing file is never replaced.
- **Rename** is a file rename plus the `title:` line, inside the rename job (AP-1291). **Trash** moves the file to `.trash/.tegg/queries/<name>.yml` (AP-1292). Tegg never deletes a query file in place.
- Values are written plain when YAML reads them back unchanged, else double-quoted (D-230). Names, keys and links are written NFC. Line endings follow the file; a missing final newline stays missing. A commit whose result equals the bytes on disk writes nothing.

### R139. Filters and operators (FR-QRY-01, -02, -03; board B; AP-1297, AP-1298, AP-1302)

A filter item is a one-key mapping: the key is an attribute key, `links_to` or `linked_from`; the value is a scalar (short for `is`) or a one-key mapping `{ <operator>: <value> }`. Attribute kinds follow types.md R10.

| Kind (R10 types) | Operators (board label → YAML) | Semantics |
| --- | --- | --- |
| Links (`links_to`, `linked_from`) | `links to` → `links_to: <v>`; `linked from` → `linked_from: <v>` | `<v>` is `this` (the host, FR-QRY-03) or `"[[target]]"` resolved like a link (FR-LNK-14: file or `id`, never title alone). An object **links to** X when the Backlinks panel of X lists it (body links, embeds, relation values, links inside attribute text; not tags; FR-LNK-01). **Linked from** X is the reverse |
| Text (`text`, `long-text`, `url`, `email`) and `title` | `is`, `is not` → `is_not`, `contains`, `is empty` → `is_empty: true`, `is not empty` → `is_not_empty: true` | compared after NFC, case- and diacritic-insensitive (D-109; AP-1302); `contains` is a substring test under the same folding |
| Select (`select`), `review` | `is`, `is not`, `is any of` → `is_any_of: [..]`, `is empty` | as Text (AP-1302); a value that isn't an option still compares by text |
| Tags (`tags`) and `multi-select` | `has any of` → `has_any_of`, `has all of` → `has_all_of`, `has none of` → `has_none_of` | tags by tag key (tags.md R79: NFC, lower case, `#` ignored), frontmatter and inline `#tags` alike; multi-select by label as Select |
| Date (`date`, `date-range` halves `<key>-start` / `<key>-end`), Date-time (`date-time`, `created`, `modified`) | `is`, `before`, `after`, `between` → `between: [a, b]` (inclusive), `today` → `today: true`, `this week` → `this_week: true`, `within next N days` → `within_next_days: N`, `overdue` → `overdue: true`, `is empty` | a date-time compares by its **local date in the machine's current zone** (D-104); `today` and the relative operators use the test clock's local date; AP-1297 defines `this week`, `within next N days`, `overdue`; the value `this` means the host Daily Note's date (AP-1298) |
| Number (`number`, C `rating`, `currency` amount) | `=` → `eq`, `≠` → `ne`, `<` → `lt`, `>` → `gt`, `between` | numeric; a non-number value never matches (and is not "empty") |
| Checkbox (`checkbox`) | `is checked` → `is: true`, `is not checked` → `is: false` | a missing value is "not checked" |
| Relation (`relation`, `source`) | `links to` → `{ links_to: <v> }`, `is empty`, `is not empty` | the attribute's own values only (FR-QRY-03 "source is this note" is `source: { links_to: this }`) |

`recurrence`, `file` and `cover`/`icon` aren't offered. **The attribute list** (board B listbox) is grouped: `Links` (Links to, Linked from), `Every object` (Title, Tags, Created, Modified, Review, Source, Aliases), then the chosen type's own attributes in schema order; with several types, only attributes the types share (same key and kind); with all types, only the first two groups.

**Broken filter** (board D; AP-1299): an item whose attribute is not an attribute of every chosen type (or of any type, for all types), whose operator isn't valid for the kind, whose value has the wrong shape, or a nested group. It is **ignored as if the row weren't there** (a group whose rows are all ignored is ignored), kept byte for byte in the file, named in the block's one-line notice, and drawn in `--danger` in the editor. A type key in `types` with no definition and no objects makes the whole query return **no results** with the notice `The type <key> doesn't exist.` (never "all types").
