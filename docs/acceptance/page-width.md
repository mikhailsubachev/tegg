### FR-SET-02 Page width: the switch on the note page (AP-755, AP-756)

- **AC-6** **The control and where it is (AP-756; contract §3).** On `note/<path>` the `toolbar` `Note toolbar` contains a `radiogroup` `Page width` with exactly two `radio`s, `Normal` (`data-command="note.width.normal"`, icon `data-icon="width-normal"`) and `Wide` (`data-command="note.width.wide"`, icon `data-icon="width-wide"`), whose accessible names are their visible texts; exactly one is `aria-checked="true"`. In the edit view the toolbar's DOM order is `Show Markdown source`, `Save state`, `Page width`, `Focus mode`, `Toggle right panel`; in the read view and the source view (⌥⌘U) the group is present with the same checked radio, immediately before `Focus mode`. The group is present on Porada, Bez hlavičky, `daily/2026-10-27` (virtual) and `new/quick-note`; it is absent on `home`, `tasks`, `type/page`, `tag/<name>`, `search` and every Settings page. In focus mode (⌘⇧\, FR-UX-02 AC-9) the group leaves with the toolbar and `.note-column[data-width]` keeps its value; leaving focus mode shows it again, unchanged. *(L5)*
- **AC-7** **A switch applies at once, to this note only.** On Porada (no entry: `Normal` checked, `data-width="normal"`), clicking `Wide` sets `aria-checked` on `Wide`, `.note-column[data-width="wide"]` within 100 ms, without a reload (the `Note body` element is the same DOM node before and after, its text and the editor's selection unchanged); clicking `Normal` reverses it. Moving to Úvodní shows `Normal` checked (its own key has no entry); Back (⌘[) shows Porada with `Wide` still checked. A note opened in the read view and switched there shows the same width when switched to the editor and the source view. *(L5)*
- **AC-8** **Drafts and virtual daily notes (AP-758).** (a) On `new/quick-note` (D-520) clicking `Wide` shows the draft wide and sends no `ui_state_set` (nothing to key); typing `Široký nápad` and ⏎ creates `Quick Notes/Široký nápad.md`, the route becomes `note/Quick Notes/Široký nápad.md` still wide, and `noteWidth` then holds exactly one new entry, `<the new file's id>: "wide"`, with no path-keyed entry; leaving a draft switched to Wide without creating it (sidebar `Inbox`) stores nothing and the next `new/quick-note` opens with the vault default. (b) `daily/2026-10-27` (no file yet, D-322) switched to Wide stores `noteWidth["Daily/2026-10-27.md"] = "wide"` at once; after its first write (typing `Ráno`) the entry is keyed by the new file's `id` and the path key is gone; reopening `daily/2026-10-27` shows `Wide`. *(L5)*
- **AC-9** **Keyboard (FR-UX-03).** From the note's type chip, ⇧Tab reaches the `Page width` group as one stop, landing on the checked radio (the unchecked radio is not a Tab stop; AP-762: the toolbar is above the note); → on `Normal` moves the focus to `Wide` and chooses it (`data-width="wide"` within 100 ms), ← back to `Normal` and chooses it; Space or ⏎ on the focused radio chooses it; the focus stays on the radio afterwards, with the indicator of app-shell FR-UX-03 AC-13 (b). A keyboard-only run (no pointer events) opens Porada from Search, reaches the group with ⇧Tab from the type chip, sets Wide with →, opens Úvodní, goes Back with ⌘[ and finds `Wide` checked. *(L5)*

### FR-STO-07 The per-note choice is machine-local (AP-753)

- **AC-4** **Stored in `ui-state.json`, keyed by `id`.** Choosing `Wide` on Porada sends exactly one `ui_state_set` whose `UiStateDto` has `version: 1` and `noteWidth: { "01JA0H0000000000000000H005": "wide" }` and every other field as the UI read it (a field a 3A-era file lacks reads as its default, AP-764); choosing `Normal` afterwards sends one more with `"normal"` (the key stays, with the new value); a second click on the already-checked radio sends nothing (AP-760). A `UiStateDto` without `noteWidth` (and `window.__TEGG_UI_STATE__` from a 3A-era file) reads as empty: every note shows the vault default. The entry follows the `id`: after the fake core renames Porada's file to `Schůzky/2026-10-07 Porada týmu.md` (same `id`, `vault:changed`, FR-SYN-03 AC-5), the renamed note (opened by its unchanged frontmatter title, its `note_read` path the new one, AP-763) opens `Wide`; entries of notes that no longer exist are left as they are (no pruning in this slice). Nothing of this is written into the vault: no `note_write`, `vault_settings_patch` or any other write command is sent by a switch. *(L5; L1 for the DTO's defaults)*
- **AC-5** **No `id`: keyed by the NFC path and re-keyed on the first edit (T2).** Opening Bez hlavičky through a route whose path is in **NFD** and choosing `Wide` stores `noteWidth["Pages/Bez hlavičky.md"] = "wide"` with the key in NFC (FR-FMT-12); opening it again through the NFC path shows `Wide`. Typing `Doplněk` into it (the first edit writes `id` and `type: page`, editor.md FR-FMT-02 AC-5) moves the entry: after `Saved`, `noteWidth` has `<the written id>: "wide"` and no longer has the path key, in one `ui_state_set` after the write; the note stays `Wide`. A file without an `id` renamed outside Tegg has no entry under its new path and shows the vault default (the consequence of AP-753; stated so the test asserts it). *(L5)*
- **AC-6** **Relaunch keeps it, the vault doesn't change.** On the built app with a temporary copy of the fixture and `TEGG_APP_SUPPORT=<temp dir>`: open Porada, choose `Wide`, open Úvodní (left at the default), quit (⌘Q), relaunch: Úvodní (the launch landing, FR-UX-02 AC-16) shows `Normal` and `data-width="normal"`; opening Porada shows `Wide` and `data-width="wide"`; `<temp dir>/ui-state.json` contains the key `01JA0H0000000000000000H005` with `wide`; every vault file's bytes and mtimes are identical to the snapshot taken before the first launch, `.tegg/vault.yml` included, and nothing was created in the vault. *(L6)*

### FR-SET-01 Settings › Vault: the vault default `page-width` (AP-754)

- **AC-11** **The row writes one line (R58; D-551).** On the inbox fixture `settings/vault` shows, after `Attachments folder` (below `Add starter types…`, keeping AC-10's Tab order), the `radiogroup` `Page width` with the radios `Normal` (`data-command="settings.pageWidth.normal"`) and `Wide` (`settings.pageWidth.wide`) and the description `For notes without their own choice.`; with no `page-width:` line, `Normal` is checked and opening the page writes nothing. Choosing `Wide` sends exactly one `vault_settings_patch` (`key: 'page-width'`, `value: 'wide'`, `base` = the file's last-read version) and the core appends exactly the line `page-width: wide` after `daily-format: YYYY-MM-DD`; every other byte of `.tegg/vault.yml` (the comment line included) is unchanged and no other file is written. Choosing `Normal` then changes only that line to `page-width: normal`; choosing the checked value sends and writes nothing. *(L4 for the bytes; L5 for the calls)*
- **AC-12** **Reading and refusing values (T2).** `vault_settings` returns `pageWidth: 'wide'` for `page-width: wide`, and `'normal'` for a missing line, `page-width: normal`, `page-width: Wide`, `page-width: huge`, `page-width:` (empty) and `page-width: 1200` (unknown reads as normal, case-sensitive, AP-754); reading writes nothing and never rewrites an unknown value. `vault_settings_patch` with `Wide`, `huge` or an empty value returns `Invalid` and writes nothing, while ` wide ` (surrounding spaces) is trimmed and written as `page-width: wide`; with a stale `base` it returns `Conflict`, writes nothing, and the page behaves as FR-SET-01 AC-3 (alert `Changed outside Tegg. Your change to Page width wasn't saved.`, reload within 2 s). The UI never offers a third value. *(L4; L5)*
- **AC-13** **The default applies to notes without a choice (AP-754, AP-759).** On a shell copy whose `vault.yml` has `page-width: wide`: Úvodní and Bez hlavičky (no entries) open with `Wide` checked and `data-width="wide"`; Porada with the entry `"normal"` opens `Normal`; `new/quick-note` and `daily/2026-10-27` open `Wide`. With Úvodní open, changing the default to `Normal` on `settings/vault` and returning (⌘[) shows Úvodní `Normal`; with Úvodní open and `vault:changed` reporting `page-width: wide` written outside Tegg, it shows `Wide` within 2 s, without a reload of the note and with zero write commands; Porada's own entry is unaffected in both cases. *(L5)*

### FR-UX-01 Two widths (AP-757; amends AC-1's wording to "in the Normal width")

- **AC-6** **Measured widths.** At window widths 1024, 1440 and 2560 px, with the right panel closed and open (288 px, sidebar 232 px): in **Normal**, `.note-column[data-width="normal"]` has computed `max-width` 760 px, `padding-left` and `padding-right` 40 px, its width is `min(760, centre pane width)` ±1 px and its left and right margins inside the centre pane are equal ±1 px; in **Wide**, `.note-column[data-width="wide"]` has computed `max-width` `none`, `padding-left` and `padding-right` 56 px, and its width equals the centre pane's width ±1 px (1440 px: 1208 closed, 920 open; 2560 px: 2328 closed, 2040 open). Opening the panel narrows a Wide column by exactly the panel's width (D-634, FR-UX-02 AC-7); in Wide the page has no horizontal scrollbar (`document.scrollingElement.scrollWidth` equals the viewport width) on Porada and on a runtime note with a 12-column table. *(L5, computed styles)*

### FR-SYN-06 A switch writes nothing to the vault (slice PW)

- **AC-35** **Zero vault writes from switching; one line from the setting.** On the fake core: switching Porada, Bez hlavičky, `daily/2026-10-27` and the `new/quick-note` draft between `Wide` and `Normal` ten times each, by radio and by palette command, sends zero `note_write`, zero `vault_settings_patch` and zero other write or create commands; every file of the fake core's vault has the same bytes and version as before and no `modified` value changed; `ui_state_set` was sent exactly once per effective change (30: none for the draft). On `settings/vault`, each change of `Page width` sends exactly one `vault_settings_patch` and the core writes exactly one file, `.tegg/vault.yml`, atomically (temp + rename, FR-SYN-02); the per-note entries in `ui-state.json` are untouched by it. *(L5; L4 for the single file)*

### FR-UX-03 Palette commands for the width (adds to app-shell.md; AP-756)

- **AC-17** **Two commands, no shortcut, note routes only.** The command registry has `note.width.normal` `Page width: Normal` and `note.width.wide` `Page width: Wide` in section `view`, with no shortcut; R4 is unchanged and FR-UX-03 AC-7 (registry integrity) and AC-8 (every control is a command: the two radios carry these ids) pass on Porada. On `note/<path>`, `daily/<date>` and `new/<type>` the palette lists both; running `Page width: Wide` sets the width as the radio does (`data-width="wide"`, `Wide` `aria-checked="true"`, one `ui_state_set`), closes the palette and returns the focus to the element that had it (D-139 rule); running the already-effective one changes nothing. On `home`, `tasks`, `type/page`, `search` and `settings/vault` they aren't run: no `ui_state_set`, no error, the route unchanged (tasks.md R45 rule). No menu-bar item is added. *(L1 for the registry; L5)*

### FR-UX-05 Themes (adds to app-shell.md)

- **AC-12** **Both themes, visible checked state.** In light and in dark, on Porada in the edit, read and source views and on `settings/vault`, with `Normal` and then `Wide` checked: axe `color-contrast` reports zero violations and FR-UX-05 AC-5 (no colour leaks) passes; the checked radio's computed `background-color` or `color` differs from the unchecked radio's in the same theme (the state isn't conveyed by `aria-checked` alone), and its text has ≥ 4.5:1 against its own background; the two icons are drawn with `currentColor` (no colour literal, FR-UX-05 AC-2); the focused radio shows the ≥ 2 px `focus` outline (app-shell FR-UX-03 AC-13 (b)). The column's own colours don't change between Normal and Wide. *(L5; L1 for the tokens the radios use)*

### NFR-OTH-02 Strings (adds to app-shell.md)

- **AC-9** **Catalog only.** The catalog has exactly the keys `note.width` `Page width`, `note.width.normal` `Normal`, `note.width.wide` `Wide`, `cmd.width.normal` `Page width: Normal`, `cmd.width.wide` `Page width: Wide`, `settings.vault.pageWidth` `Page width`, `settings.vault.pageWidthNote` `For notes without their own choice.`, and the two commands' titles are these keys (FR-UX-03 AC-7). With the pseudo-locale, every visible text and accessible name of the toolbar group and its radios, the two palette rows, the Settings row and its description is inside `⟦ ⟧`; the note's title and body stay user content. *(L1 for the keys; L5)*
