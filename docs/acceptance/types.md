## Reference tables

### R10. Attribute types (FR-TYP-02, FR-TYP-03, dialect §3)

The `type` values a type file may use for an attribute, in the order the `Type` control offers them. Written forms are dialect §3; "Valid when read" decides the invalid-value display of FR-EDT-07 AC-7 (never a rewrite).

| `type` in the type file | Label (catalog) | Panel control | Written as | Valid when read |
| --- | --- | --- | --- | --- |
| `text` | Text | single-line text field | plain scalar; double-quoted when YAML would read it as anything but this string (D-230) | any scalar (numbers and booleans are shown as written) |
| `long-text` | Long text | multi-line field (⏎ new line, ⌘↩ commits) | plain scalar on one line, a `\|-` block for several lines | any scalar |
| `number` | Number | text field | YAML number (`12`, `3.5`); input accepts the region's decimal separator and group spaces (D-230) | an unquoted YAML int or float |
| `checkbox` | Checkbox | checkbox | `true` / `false` | a YAML 1.2 boolean |
| `date` | Date | date field (typed or picker) | `2026-10-07` (FR-FMT-11) | `YYYY-MM-DD` (plain or quoted) that is a real calendar date |
| `date-time` | Date-time | date and time fields | ISO 8601 with the offset of that moment in the machine's zone (D-230) | ISO 8601 with offset or `Z` |
| `date-range` | Date range | two date fields in one row | `<key>-start` and `<key>-end`, each a date | each half valid as `date`; end not before start |
| `select` | Select | list of the options | the option label, plain scalar | a string equal to an option label (NFC, exact) |
| `multi-select` | Multi-select | list of the options, several chosen | block list of labels (flow kept if the entry is flow, D-230) | a list whose every item is an option label |
| `url` | URL | text field | plain scalar | an absolute `http` or `https` URL |
| `email` | Email | text field | plain scalar | `local@domain` with a dot in the domain, no spaces |
| `relation` | Relation | object chips and a picker | `"[[target]]"`; with `multiple: true` a block list of them | a quoted wikilink string, or a list of them |

Attribute options in the type file: `options` (Select, Multi-select: `{ label, color }`), `to` (Relation: list of allowed type keys, absent = any type), `multiple` (Relation: `true` or absent), `default`, `required` (`true` or absent), `description`. Not offered for new properties: `rating`, `currency`, `file` (C, FR-TYP-02) and the system-only `color` and `recurrence` (new-empty Tag and Task); they are read and shown read-only (FR-TYP-02 AC-4, AC-5).

### AR-07 Versioned type definitions (`tegg-schema`)

- **AC-1** **Every written type file has a version.** Every `.tegg/types/*.yml` Tegg writes (new vault, new type, starter types, any type-settings change) has `version: 1` as its first key after the header comment; `tegg-schema` exposes the supported version as one constant (`CURRENT_VERSION = 1`). The new user type of FR-TYP-01 AC-2 is byte-identical to `tests/fixtures/types/expected/čajovna.yml`. *(L4)*
- **AC-2** **A missing version (D-235).** A runtime copy of `osoba.yml` without `version` is read as version 1 with no warning; opening the vault, the type page and the type settings write nothing; the first change the user makes writes `version: 1` as the first key after the header comment and changes nothing else but the changed field. *(L4; L5)*
- **AC-3** **A newer version (D-235).** `budoucí.yml` (`version: 2`, unknown key `views`) is read: its name, plural, folder, icon, colour and attributes of R10 types are used in the sidebar, on the type page and in the panel of its objects, and the panel's values are editable. Type settings shows every control disabled with the catalog message `Made by a newer version of Tegg. Read-only.` and `Delete type` disabled; no command that writes the type file is sent, and the core refuses such a write (`NewerVersion`). The file's bytes are unchanged at the end of the test. *(L4; L5)*
- **AC-4** **Invalid files.** `rozbitý.yml` is reported invalid with the error at line 4; runtime variants with `version: 0`, `version: "1"` and `version: 1.5` are invalid too (version must be a positive integer). An invalid type keeps a sidebar entry named by its key with the marker `Invalid type definition`; its type page lists its objects; its type settings show the error text and line, read-only, and offer nothing that writes. Opening, indexing and showing never rewrite it (NFR-REL-03). *(L4; L5)*
- **AC-5** **Minimal writes (D-235).** Changing `osoba`'s colour to `teal` changes only the `color:` line of `osoba.yml`: the comment `# Barvu vybrala Jana.`, the unknown key `poznámka-pro-mě`, key order, quoting and the final newline stay byte-identical. The same holds for each other General field, for `review`, for `preview`, and for adding a property (one new item appended at the end of `attributes`). A change back to the previous value is written, and a change that leaves the value equal writes nothing (FR-SYN-06). *(L4)*
- **AC-6** **Round trip.** For every type file in `new-empty/`, `new-starter/`, `shell/` and `types/` except `rozbitý.yml`, `tegg-schema` parse then serialize without changes returns identical bytes, and parse → canonical write of a new file → parse gives an equal definition. *(L4)*
- **AC-7** **Nothing only in the index (AR-01, NFR-POR-03).** After deleting the index directory and reopening the vault, the type list, sidebar counts, type page rows (FR-TYP-09 AC-2) and every panel's schema are identical to before. *(L4)*

### FR-TYP-01 Create, edit and delete user types

- **AC-1** **New type dialog.** The sidebar's `New type` button (enabled now, R3) and the palette command `New type…` open the dialog `New type` with the fields `Name` (focused) and `Plural name` and the buttons `Create` and `Cancel`. `Cancel`, Esc and closing write nothing. *(L5)*
- **AC-2** **What Create writes.** With Name `Čajovna` and Plural `Čajovny`, `Create` writes exactly one file, `.tegg/types/čajovna.yml` (NFC name, atomic, FR-SYN-02), byte-identical to `tests/fixtures/types/expected/čajovna.yml`; no folder `Čajovny/` and no template is created (folders come with the first object, FR-SYN-06). Within 1 s the sidebar lists `Čajovny` in D-121/D-122 order with the count 0, and the route is `type-settings/čajovna` with the focus on its heading (D-130). If a file `.tegg/types/čajovna.yml` appears on disk between the check and the write, nothing is overwritten and the dialog shows `A type with this name already exists`. *(L5; L4 for the file; L6 once)*
- **AC-3** **Name rules (D-222).** `Create` is refused with a catalog message naming the reason, and writes nothing, for: an empty or whitespace-only Name or Plural; a Name whose key (D-96: NFC, lower case, whitespace as `-`) equals an existing type's key, including system types (`Page`, `quick note`, `QUICK NOTE`) and `čajovna` typed in NFD after Čajovna exists; a Name or Plural containing `/ : \ * ? " < > | # ^ [ ]` or a control character (D-52, D-68); a key longer than 200 UTF-8 bytes (D-51); a Plural that equals another type's folder (case-insensitive, NFC). A Name whose key equals a `type` value used by objects without a definition (`recept` in the shell fixture, D-121) is allowed, and those objects become this type's objects. *(L5; L4 for the rules)*
- **AC-4** **Editing General (D-221).** In `type-settings/schůzka`, changing Name to `Porada`, Plural to `Porady`, Description, Icon (R14) and Color (R14) each writes only `.tegg/types/schůzka.yml` (AR-07 AC-5) within 1 s, after which the state shows `Saved`; the sidebar, the type page header, the breadcrumb and the type chip of an open Schůzka note update without a reload. The file keeps its name `schůzka.yml`, every note keeps `type: schůzka`, and no note file is written (bytes, mtime and inode unchanged). Name and Plural follow the rules of AC-3; an invalid entry shows the message under the field and isn't written. *(L5; L4 for the files)* *(breadcrumb part removed by D-315: the note page has no breadcrumb)*
- **AC-5** **Folder (D-226; verifies data-safety FR-STO-01… AC-2, new-object part).** Changing `Folder in the vault` to `Práce/Porady` writes `folder: Práce/Porady`; the existing Schůzka files aren't moved; the next Schůzka created goes to `Práce/Porady/` (folders created then). The field's help text is `New objects go here. Moving existing objects comes in v1.0.` and `Move existing objects` is disabled `Coming in v1.0`. Refused with a message, nothing written: empty; absolute; containing `..`; a segment starting with `.`; `_templates`, `_attachments`, `.trash`, `.tegg` or a path under them; a segment with a character of AC-3; the folder of another type (case-insensitive, NFC). *(L5; L4 for the rules)*
- **AC-6** **Changes from outside.** When another program changes `osoba.yml`'s colour, the sidebar, the type page and an open type settings page show it within 2 s (NFR-PERF-08), with no write.
