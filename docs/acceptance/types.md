# Acceptance Criteria: Types and attributes (MS3 slice 3D)

See [README](README.md) for conventions. Milestone MS3 (BRD §11.2), slice **3D "Types and attributes"** (D-115; plan `docs/plans/ms3-implementation-plan.md` §3, §4.2). Notes become typed objects: `tegg-schema` reads and writes versioned type files (AR-07), the note page gets the editable attribute panel on top of the 3C editor (FR-EDT-07; the owner asked for it explicitly: property values can't be changed today), types get their settings page and a full type page, and a new vault can start from the starter types (FR-VLT-02, D-92). Exit goal: the owner uses typed objects (Meetings, People, Projects, Reading Notes).

**Status: accepted, 2026-10-14.** Writing these criteria raised AP-161…AP-184 (end of this file); the owner accepted all proposals as D-221…D-244 (BRD v1.38). A criterion that cites a decision follows it.

**Scope.** AR-07, FR-TYP-01, -02, -03, -05, -06, -08 (editing), -09, -11, -12, -13, FR-EDT-07, the MS3 parts of FR-TYP-04 and FR-TYP-07 (D-94: renames, value rewrites and file moves stay MS4), FR-VLT-02 (starter vault, D-92). **Out of scope:** renaming an attribute key and rewriting values in files (FR-TYP-04, MS4, links.md); moving files on a type change or folder change (FR-STO-04, MS4); bulk type changes and the backup zip (FR-HIS-04, D-57, MS4); templates beyond copying the default template (FR-TPL, v1.0); saved views, query builder, board/calendar views and editable cells (FR-QRY, v1.0); Task status labels (FR-TSK-02, MS5); the type picker of New object (FR-VLT-05, MS5); Inbox (FR-INB, MS5); previews and embed cards that show preview attributes (FR-LNK-10, v1.0; FR-EMB, MS4); object icon and cover (FR-TYP-14 removed, D-217).

## Reference tables

### R10. Attribute types (FR-TYP-02, FR-TYP-03, dialect §3)

The `type` values a type file may use for an attribute, in the order the `Type` control offers them. Written forms are dialect §3; "Valid when read" decides the invalid-value display of FR-EDT-07 AC-7 (never a rewrite).

| `type` in the type file | Label (catalog) | Panel control | Written as | Valid when read |
| --- | --- | --- | --- | --- |
| `text` | Text | single-line text field | plain scalar; double-quoted when YAML would read it as anything but this string (D-230) | any scalar (numbers and booleans are shown as written) |
| `long-text` | Long text | multi-line field (⏎ new line, ⌘↩ commits) | plain scalar on one line, a `\|-` block for several lines | any scalar |
| `number` | Number | text field | YAML number (`12`, `3.5`); input accepts the region's decimal separator and group spaces (D-230) | an unquoted YAML int or float |
| `checkbox` | Checkbox | checkbox | `true` / `false` | a YAML 1.2 boolean |
| `date` | Date | date field (typed or picker) | `2026-10-07` (FR-FMT-11) | `YYYY-MM-DD` (plain or quoted) that is a real calendar date |
| `date-time` | Date-time | date and time fields | ISO 8601 with the offset of that moment in the machine's zone (D-230) | ISO 8601 with offset or `Z` |
| `date-range` | Date range | two date fields in one row | `<key>-start` and `<key>-end`, each a date | each half valid as `date`; end not before start |
| `select` | Select | list of the options | the option label, plain scalar | a string equal to an option label (NFC, exact) |
| `multi-select` | Multi-select | list of the options, several chosen | block list of labels (flow kept if the entry is flow, D-230) | a list whose every item is an option label |
| `url` | URL | text field | plain scalar | an absolute `http` or `https` URL |
| `email` | Email | text field | plain scalar | `local@domain` with a dot in the domain, no spaces |
| `relation` | Relation | object chips and a picker | `"[[target]]"`; with `multiple: true` a block list of them | a quoted wikilink string, or a list of them |

Attribute options in the type file: `options` (Select, Multi-select: `{ label, color }`), `to` (Relation: list of allowed type keys, absent = any type), `multiple` (Relation: `true` or absent), `default`, `required` (`true` or absent), `description`. Not offered for new properties: `rating`, `currency`, `file` (C, FR-TYP-02) and the system-only `color` and `recurrence` (new-empty Tag and Task); they are read and shown read-only (FR-TYP-02 AC-4, AC-5).

### AR-07 Versioned type definitions (`tegg-schema`)

- **AC-1** **Every written type file has a version.** Every `.tegg/types/*.yml` Tegg writes (new vault, new type, starter types, any type-settings change) has `version: 1` as its first key after the header comment; `tegg-schema` exposes the supported version as one constant (`CURRENT_VERSION = 1`). The new user type of FR-TYP-01 AC-2 is byte-identical to `tests/fixtures/types/expected/čajovna.yml`. *(L4)*
- **AC-2** **A missing version (D-235).** A runtime copy of `osoba.yml` without `version` is read as version 1 with no warning; opening the vault, the type page and the type settings write nothing; the first change the user makes writes `version: 1` as the first key after the header comment and changes nothing else but the changed field. *(L4; L5)*
- **AC-3** **A newer version (D-235).** `budoucí.yml` (`version: 2`, unknown key `views`) is read: its name, plural, folder, icon, colour and attributes of R10 types are used in the sidebar, on the type page and in the panel of its objects, and the panel's values are editable. Type settings shows every control disabled with the catalog message `Made by a newer version of Tegg. Read-only.` and `Delete type` disabled; no command that writes the type file is sent, and the core refuses such a write (`NewerVersion`). The file's bytes are unchanged at the end of the test. *(L4; L5)*
- **AC-4** **Invalid files.** `rozbitý.yml` is reported invalid with the error at line 4; runtime variants with `version: 0`, `version: "1"` and `version: 1.5` are invalid too (version must be a positive integer). An invalid type keeps a sidebar entry named by its key with the marker `Invalid type definition`; its type page lists its objects; its type settings show the error text and line, read-only, and offer nothing that writes. Opening, indexing and showing never rewrite it (NFR-REL-03). *(L4; L5)*
- **AC-5** **Minimal writes (D-235).** Changing `osoba`'s colour to `teal` changes only the `color:` line of `osoba.yml`: the comment `# Barvu vybrala Jana.`, the unknown key `poznámka-pro-mě`, key order, quoting and the final newline stay byte-identical. The same holds for each other General field, for `review`, for `preview`, and for adding a property (one new item appended at the end of `attributes`). A change back to the previous value is written, and a change that leaves the value equal writes nothing (FR-SYN-06). *(L4)*
- **AC-6** **Round trip.** For every type file in `new-empty/`, `new-starter/`, `shell/` and `types/` except `rozbitý.yml`, `tegg-schema` parse then serialize without changes returns identical bytes, and parse → canonical write of a new file → parse gives an equal definition. *(L4)*
- **AC-7** **Nothing only in the index (AR-01, NFR-POR-03).** After deleting the index directory and reopening the vault, the type list, sidebar counts, type page rows (FR-TYP-09 AC-2) and every panel's schema are identical to before. *(L4)*

### FR-TYP-01 Create, edit and delete user types

- **AC-1** **New type dialog.** The sidebar's `New type` button (enabled now, R3) and the palette command `New type…` open the dialog `New type` with the fields `Name` (focused) and `Plural name` and the buttons `Create` and `Cancel`. `Cancel`, Esc and closing write nothing. *(L5)*
- **AC-2** **What Create writes.** With Name `Čajovna` and Plural `Čajovny`, `Create` writes exactly one file, `.tegg/types/čajovna.yml` (NFC name, atomic, FR-SYN-02), byte-identical to `tests/fixtures/types/expected/čajovna.yml`; no folder `Čajovny/` and no template is created (folders come with the first object, FR-SYN-06). Within 1 s the sidebar lists `Čajovny` in D-121/D-122 order with the count 0, and the route is `type-settings/čajovna` with the focus on its heading (D-130). If a file `.tegg/types/čajovna.yml` appears on disk between the check and the write, nothing is overwritten and the dialog shows `A type with this name already exists`. *(L5; L4 for the file; L6 once)*
- **AC-3** **Name rules (D-222).** `Create` is refused with a catalog message naming the reason, and writes nothing, for: an empty or whitespace-only Name or Plural; a Name whose key (D-96: NFC, lower case, whitespace as `-`) equals an existing type's key, including system types (`Page`, `quick note`, `QUICK NOTE`) and `čajovna` typed in NFD after Čajovna exists; a Name or Plural containing `/ : \ * ? " < > | # ^ [ ]` or a control character (D-52, D-68); a key longer than 200 UTF-8 bytes (D-51); a Plural that equals another type's folder (case-insensitive, NFC). A Name whose key equals a `type` value used by objects without a definition (`recept` in the shell fixture, D-121) is allowed, and those objects become this type's objects. *(L5; L4 for the rules)*
- **AC-4** **Editing General (D-221).** In `type-settings/schůzka`, changing Name to `Porada`, Plural to `Porady`, Description, Icon (R14) and Color (R14) each writes only `.tegg/types/schůzka.yml` (AR-07 AC-5) within 1 s, after which the state shows `Saved`; the sidebar, the type page header, the breadcrumb and the type chip of an open Schůzka note update without a reload. The file keeps its name `schůzka.yml`, every note keeps `type: schůzka`, and no note file is written (bytes, mtime and inode unchanged). Name and Plural follow the rules of AC-3; an invalid entry shows the message under the field and isn't written. *(L5; L4 for the files)*
- **AC-5** **Folder (D-226; verifies data-safety FR-STO-01… AC-2, new-object part).** Changing `Folder in the vault` to `Práce/Porady` writes `folder: Práce/Porady`; the existing Schůzka files aren't moved; the next Schůzka created goes to `Práce/Porady/` (folders created then). The field's help text is `New objects go here. Moving existing objects comes in MS4.` and `Move existing objects` is disabled `Coming in MS4`. Refused with a message, nothing written: empty; absolute; containing `..`; a segment starting with `.`; `_templates`, `_attachments`, `.trash`, `.tegg` or a path under them; a segment with a character of AC-3; the folder of another type (case-insensitive, NFC). *(L5; L4 for the rules)*
- **AC-6** **Changes from outside.** When another program changes `osoba.yml`'s colour, the sidebar, the type page and an open type settings page show it within 2 s (NFR-PERF-08), with no write. A type file added outside Tegg appears in the sidebar within 2 s; a deleted one disappears, and its objects show under the "no type definition" entry (D-121). *(L4 for the watcher; L5)*
- **AC-7** **Never overwrite an external change (NFR-REL-02, D-235).** Every type-file write carries the version of the file as last read. When the file changed on disk since (L5: the fake core changes it without an event; L4: other bytes on disk), the write is refused with `Conflict`, the page reloads the disk version, and a non-modal `alert` says `Changed outside Tegg. Your change to <field label> wasn't saved.`; the file keeps the external bytes. *(L4; L5)*
- **AC-8** **Templates and Views sections (R12).** The Templates section of Nápad shows `_templates/Nápad/Nápad.md` as text, marked Default; `New template` and `Edit` are disabled `Coming in v1.0`. The Views section shows `All Nápady` marked Default; `Add view` and `Edit` are disabled `Coming in v1.0`. *(L5)*
- **AC-9** **Strings, themes, palette.** Every label, message and help text of the type settings page, the New type dialog and the type page comes from the catalog (user content excepted); counts use plural categories (D-133; the Czech test catalog shows `1 objekt`, `3 objekty`, `5 objektů`). FR-UX-05 AC-4 and AC-5 pass on `type-settings/projekt` with every property expanded, on the New type dialog and on `type/projekt`, in light and dark. The R13 commands are listed in the palette. *(L1; L5)*

### FR-TYP-02 Attribute types

- **AC-1** **Offered types.** The `Type` control of a new property lists exactly the 12 rows of R10 in that order, with their labels; Rating, Currency and File/attachment (C) and the system-only `color` and `recurrence` aren't offered. *(L5)*
- **AC-2** **Validity.** `tegg-schema`'s value check (the same rules in the UI, D-241) reports every R10 "valid when read" rule: on Rozpočet every value is valid; on Chybné exactly `stav`, `období`, `rozpočet`, `aktivní`, `oblasti` and `web` are invalid; on Ve stránkách `datum` and both relations; on Petr `e-mail`. A YAML date written quoted (`'2026-10-07'`) and a `Z` date-time are valid. *(L4; L1)*
- **AC-3** **Date range is one field (verifies file-format FR-FMT-11 AC-4).** `období` is one row `Období` with two date fields. - **AC-1** **Add property.** `Add property` (type settings) and `Add column` (type page, FR-TYP-09 AC-7) open a new property row with `Name` focused.   *(L5; L4 for the bytes)*

- **AC-8** **Description.** A property's `Description` is written as `description:` and shown in the panel as the value control's accessible description and as a tooltip on its label (`místo`: `Kde se schůzka konala`). *(L5)*

- **AC-12** **One creation path (D-232; D-92, D-96, FR-TYP-12).** Every way of creating an object (⌘N New object, the switcher's create item, `[[` create in the editor, the type page's `New <Name>`, a relation's `Create`) goes through one core command with a type and a title and writes one file in the type's folder with: `id`, `type` (the key), `title`, then the type's attributes in schema order with their value from the default template's frontmatter if it sets them, else the `default`, else omitted; then keys of the template's frontmatter that aren't attributes, in template order; then `review: unreviewed` if the type's review workflow is on or locked; then `created`, `modified`; then the template's body verbatim. ### FR-TYP-13 Exactly one type (D-239)

- **AC-5** **Written values (R10, D-230).** With the zone Europe/Prague and region `cs`, committing these values writes exactly:
  (a) Text `místo`: `Praha 1` → `místo: Praha 1`; `ano: ne` → `místo: "ano: ne"`; `123` → `místo: "123"`; `true` → `místo: "true"`; `2026-10-07` → `místo: "2026-10-07"`; `[[Cíl]]` → `místo: "[[Cíl]]"`; `#doma` → `místo: "#doma"`; `Plzeň` typed in NFD → NFC bytes.   (b) Long text `poznámka`: `Řádek 1`, ⏎, `Řádek 2`, ⌘↩ → `poznámka: |-`, `  Řádek 1`, `  Řádek 2`.
