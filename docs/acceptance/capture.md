# Acceptance Criteria: Quick Capture, default type and settings (MS5 slice 5B)

See [README](README.md) for conventions. Milestone MS5 (BRD §11.2), slice **5B "Capture and Inbox"** (`docs/plans/mvp-daily-use-plan.md` §3 row 4; D-14, D-24, D-30, D-69…D-71, D-376, D-515). Capture from anywhere: the menu bar icon and the global hotkeys ⌃⌥Space / ⌃⌥T open a small pre-warmed capture window (spike S3, `spikes/s3-platform/FINDINGS.md`; design `design/edit-note-page/QuickCapture.dc.html`) that works with the main window closed, opens in < 300 ms, and only creates: one new object of the chosen type with `review: unreviewed` and a `captured` time stamp, so it lands in the Inbox ([inbox.md](inbox.md)). The vault's default type is preselected there and in every other create path (FR-VLT-05) and is set in Settings: Vault (FR-SET-01); the menu bar icon and launch at login are set in Settings: Menu bar and startup (FR-SET-05); hotkeys that can't be registered are shown in Settings (D-71). The app runs as a single instance.

**Status: approved, 2026-10-19.** Points AP-467…AP-481 (end of this file) are decided as D-539…D-553 (BRD v1.72); a criterion naming an AP follows that decision. AP-494 (FR-SET-03, added with D-565) is decided as D-566. The Inbox, its actions, the review attribute, the final sidebar and the slice's registry changes are in [inbox.md](inbox.md) (AP-482…AP-493).

**Why two files.** Capture is native shell work (a second window, the status item, global hotkeys, single instance, capabilities) tested mostly on the built app (L6) and in the shell's Rust tests; the Inbox is a React page that rewrites existing notes (T1/T2), tested at L1/L4/L5 with a few L6 checks. ### R57. What a capture writes (FR-CAP-04, FR-TSK-10; AP-467, AP-468, AP-480)

- **Title (AP-467):** the first line of the text that holds non-space characters, as plain text by the conversion rules of D-491: a leading heading marker (`#`…`######` and a space), list marker (`- `, `* `, `+ `, `1. `, `1) `), checklist marker (`[ ] `, `[x] ` after a list marker) or quote marker (`> `) is dropped; formatting markers are dropped (`**Důležité:**` → `Důležité:`); a link becomes its alias, else its target's title; trailing `#tag` tokens are removed and go to `tags`; NFC; leading and trailing spaces trimmed. A title that ends up empty (the line was only tags) is `Untitled` (D-523).
- **Body (AP-467):** the lines after the title line; leading blank lines and trailing blank lines dropped, other lines byte for byte (trailing spaces kept); when the title line held a link, that line (marker and trailing tags removed) is kept as the body's first paragraph, then a blank line, then the rest; lines end with `\n` (CRLF typed or pasted becomes `\n`, a new file is canonical, dialect §2); the whole text is NFC; the body ends with exactly one `\n`, or is empty (the file then ends with `---\n`). Markdown is kept as typed: links, inline `#tags`, lists, code.
- **Frontmatter (AP-468, D-232, D-470):** `id`, `type` (the type key, D-96), `title`, the type's schema attributes in schema order (template value, else default, else omitted; for a Task: `status` = the first Open-state option, D-470, and `priority`, `due` from R55's fields), the template's other frontmatter keys in template order (D-524: the template's body is not used; template keys `id, type, title, tags, review, captured, created, modified` are ignored, as D-346), `tags` (the tag field's chips in order, then the title's trailing tags, duplicates dropped case-insensitively after NFC, flow list), `review: unreviewed` (also on types whose review workflow is off, FR-CAP-04), `captured`, `created`, `modified`: all three the same instant of the save, ISO 8601 with the machine zone's offset at that instant (FR-FMT-11). Values YAML would misread are double-quoted (D-230).
- **File:** the type's folder as defined at the moment of the save (FR-TYP-01 AC-5; folders created as needed), stem `sanitize(title)` (D-51, D-52, D-68, D-80), free vault-wide (D-291: ` (2)`, ` (3)`…), written once, atomically and create-exclusive (`RENAME_EXCL`, FR-SYN-02), through the capture window's only write command (AP-480). No `Tags/<tag>.md` is written (D-185).

### FR-CAP-01 The capture window

- **AC-1** **From the status item (R56).** With the main window closed and Finder frontmost, clicking the status item shows the window `Quick Capture` below it within 1 s, with the focus in `Capture text`, `Type: Quick Note` (the vault's default type), no Due or Priority control, and `Saves to <vault name>`; the main window stays hidden. Right-click shows the R56 menu; `Quick Capture` and `New Task` open the window as the hotkeys do (FR-CAP-05 AC-1, AC-2), `Open Tegg` shows the main window, `Settings…` shows `settings/appearance`, `Quit Tegg` quits. *(L6; L5 for the window's content)*
- **AC-2** **Elements and order (R55).** The capture page has exactly R55's elements with their roles and names, in R55's Tab order, the caret starting in `Capture text`; Shift-Tab from `Capture text` reaches `Discard`, then `Type`. *(L5)*
- **AC-3** **Type selector (AP-469).** `Type: Quick Note` opens the `Type` menu with exactly `Page`, `Task`, `Quick Note` (`Vault default`), `Nápad`, `Schůzka` in that order (region `cs`; with `en` the same, D-122), each with its type icon; no Daily Note, Tag, Image or PDF. ↑/↓ move, ⏎ chooses, Esc closes and returns the focus to the button. Choosing `Task` shows `Due: None` and `Priority: None` after the text; choosing `Nápad` afterwards hides them, and a due date or priority set while Task was chosen isn't written. *(L5)*
- **AC-4** **Enter and ⌘↩ (D-69).** Typing `Řádek jedna`, ⏎, `Řádek dva` gives two lines in `Capture text` and saves nothing. ⌘↩, from any control of the window, saves once (R57) and hides the window; the `Save capture` button does the same. On the built app the window is hidden within 300 ms of ⌘↩ and the app that was frontmost before the trigger is frontmost again with the key focus (Finder). *(L5; L6)*
- **AC-5** **Markdown is kept (R57).** Capturing the text `Schůzka k webu` ⏎ `**Program:**` ⏎ `- [ ] projít [[Plán webu]]` ⏎ `- termín #práce` writes the body `**Program:**\n- [ ] projít [[Plán webu]]\n- termín #práce\n` byte for byte; within 2 s Plán webu's backlinks list the new note (D-368) and `link_resolve` from it returns `Pages/Plán webu.md`; `#práce` in the body counts as a tag of the note (D-185) and isn't added to `tags:`. *(L1 for the bytes; L4 for the resolution; L5)*
- **AC-6** **Tags field.** Typing `nák` in `Add tag…` lists `#nákup` first; ⏎ adds the chip `#nákup`; typing `výlet` then a space (or `,`, or ⏎) adds `#výlet`; a leading `#` typed by the user is not doubled; ⌫ in the empty field removes the last chip; `Remove #nákup` removes that chip. `Nákup` typed after `#nákup` is not added again (case-insensitive, NFC). The note gets `tags: [nákup, výlet]` and no `Tags/` file is written. A tag typed in NFD is written NFC. *(L1 for the list; L5)*
- **AC-7** **Nothing to save.** With `Capture text` empty, or only spaces and line breaks, ⌘↩ and `Save capture` show `Nothing to save` in `Capture status`, keep the window open, and write nothing; chips alone don't make a capture. *(L5; L6 as S3-QA AC-2)*
- **AC-8** **Esc, Discard and the draft (AP-470, T1).** Esc with empty text and no chips hides the window and stores nothing. Esc with text hides the window and keeps the text, the chosen type, the chips and the Due/Priority values as a draft: the next open by any trigger shows them again with the caret at the end of the text (⌃⌥T switches the type to Task; the status item and ⌃⌥Space keep the draft's type). The draft is stored in Application Support (`capture-draft` in the machine-local store, FR-STO-07), survives quit and relaunch, and is never written into the vault. `Discard` clears the text, chips and fields, removes the draft and hides the window; nothing is written. A successful save removes the draft. *(L5; L6 for quit and relaunch)*
- **AC-9** **Window behaviour (AP-470).** Opened from the status item the window sits below it; opened by a hotkey it is centred horizontally in the upper third of the screen with the pointer. Clicking into another app doesn't hide the window or change its text; it stays above that app's windows until it is saved, dismissed with Esc or discarded. Pressing ⌃⌥Space while it is open focuses it and keeps everything; ⌃⌥T while it is open also sets the type to Task. *(L6)* Opening it while a full-screen app is frontmost on another Space shows it on that Space without switching Spaces. *[manual]*
- **AC-10** **A failed save keeps the text (T1).** When the write fails (L5: fake core `Io` on `capture_create`; L6: `Quick Notes/` made read-only), the window stays open with the text, chips and fields unchanged, `Capture status` says `Couldn’t save. Your text is kept.` with `Try again`; no `.md` file and no `.tegg-tmp` file is left. After the folder is made writable again, `Try again` writes the note once. *(L5; L6)*
- **AC-11** **No vault, or another vault (AP-474).** With no vault open (the chooser is shown), every trigger opens the window with `Open a vault in Tegg first.`, `Open Tegg` and `Save capture` aria-disabled; nothing is written. When the vault named in `Saves to …` was closed or switched (D-219) while the window was open, ⌘↩ writes nothing, keeps the text and shows `"<vault>" isn't open any more. Your text is kept.`; the next open shows the new vault's name. *(L5; L6 for the no-vault case)*
- **AC-12** [MS6] **Images and PDFs (FR-ATT-01, FR-ATT-07; AP-473).** Until slice 6A the drop zone `Add an image or PDF` is aria-disabled with `Coming in MS6`; pasting a clipboard image into `Capture text` inserts nothing and shows `Images and PDFs can be added from MS6.`; dropping a file on the window does nothing; nothing is written (5B part, verified in 5B). From 6A: pasting or dropping a PNG creates the Image object and the file in `_attachments/` (FR-ATT-07) and the capture's body ends with its `![[<file>]]` embed; one capture writes the note, the Image object and the file. *(L5; L6)*
- **AC-13** **Confirmation (AP-471).** After saving `Koupit dárek pro Janu` as a Quick Note, a panel shows `Saved to Inbox` and `Quick Note · Koupit dárek pro Janu` for 4 s without becoming key (Finder keeps the key focus); its `Open` shows the main window on `note/Quick Notes/Koupit dárek pro Janu.md` with the caret in the body (D-247). *(L6; L5 for the panel's content)*
- **AC-14** **Strings and themes.** Every text of R55, R56 and the confirmation panel is an R59 catalog key (pseudo-locale check, NFR-OTH-02 AC-3: only type names, tag names, priority labels, the vault name and typed text outside `⟦ ⟧`). - **AC-25** [MS5] **Settings write one file per change.** Each committed change on `settings/vault` writes exactly one file (`vault.yml` or `daily-note.yml`); opening the Settings pages, toggling `Show Tegg in the menu bar` and `Open Tegg at login`, and `Try again` on `settings/shortcuts` write nothing in the vault. *(L5; L6 for the switches)*
