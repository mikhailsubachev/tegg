# Acceptance Criteria: Trash, images and PDFs (MS6 slice 6A)

See [README](README.md) for conventions. Milestone MS6 (BRD §11.2), slice **6A "Trash and images"** (`docs/plans/mvp-daily-use-plan.md` §3 row 5; D-17, D-18, D-27, D-42, D-102, D-376). Objects can be moved to the trash from everywhere the boards show `Move to trash`, are listed in a Trash view, restored to where they were or deleted for good. Images and PDFs are added by paste, drop and a file picker, in notes and in the capture window; each becomes an Image or PDF object with its file in the attachments folder, and notes embed the file (`![[photo.png]]`). With the slice, **Home leaves the sidebar** (owner, 2026-10-22): Home is v1.0 (D-515).

**Status: draft, 2026-10-22.** The owner decided AP-529…AP-533 on 2026-10-22 (proposed as D-609…D-613, BRD v1.78). AP-534…AP-543 (end of this file) are pending; a criterion naming one follows its recommendation until it is decided.

### FR-HIS-01 Trash: move, list, restore, delete permanently

- **AC-1** **Move to trash from a note (T1).** On `note/Tasks/Koupit semínka.md`, `More › Move to trash` and ⌘⌫ (with the focus outside a text selection in the editor: in the body, ⌘⌫ keeps deleting to the line start) move the file to `.trash/Tasks/Koupit semínka.md` with `note_trash(path, base)` (D-195): one rename, the bytes and mtime untouched, nothing else written. No confirmation (AP-536); the app goes Back (or to the Inbox when there's no history), the live region and a toast say `Moved "Koupit semínka" to the trash` with `Undo`, which restores it (AC-5) and returns to the note. The note's unsaved edits are saved first (autosave flush, D-196); a save that fails stops the trash with the save's alert. *(L4; L5; L6 once)*
- **AC-2** **Never trash a changed file (NFR-REL-02, T1).** When the file changed on disk without an event, `note_trash` refuses with `Conflict`, nothing moves, the note reloads, and the alert `"Koupit semínka" changed outside Tegg. It wasn't moved to the trash.` appears. *(L4; L5)*
- **AC-3** **Everywhere the boards show it.** `Move to trash` works the same from the task card menu (tasks.md R43), the Inbox triage menu, ⌫ on a focused Inbox card and the Inbox selection toolbar (inbox.md FR-INB-02 AC-10, one rename per item; `Moved 3 items to the trash`; Undo restores all three), the Type page's object rows (context menu and ⌘⌫ on a focused row), and the palette on a note page. A Daily Note can be trashed; its virtual successor shows again for that date (D-321). A virtual Daily Note or an unsaved new object (D-523) has nothing to trash: the command is aria-disabled `Nothing to delete yet.`. *(L5)*
- **AC-4** **Trash list (R70, R71).** `trash` (sidebar `Trash`, palette `Go to Trash`) lists the fixture's six entries in R71's order with R70's content: T3 as one row `Smazaný obrázek` (image), T2 `Zahrada` (`Pages`), T4 `osiřelý.jpg` (`_attachments`, `data-kind="file"`), T5 `Hotovo` (task), Folder `Recepty` with `1 objects` → `1 object` (plural forms), T1 `Stará poznámka`. The Šablona and live notes aren't listed. The list follows the file system live within 2 s (another program moving a file into or out of `.trash/` adds or removes its row). **(TZ)** *(L4 for the core list; L5)*
- **AC-5** **Restore (T1).** `Restore "Stará poznámka"` (or R on the focused row) moves T1 back to `Quick Notes/Stará poznámka.md` with one rename, bytes and mtime untouched; the row leaves, the live region says `Restored "Stará poznámka"`, and within 2 s it is in search, the switcher, backlinks (Odkazy) and the Inbox rules again (`review: reviewed` keeps it out of the Inbox). Restoring T2 (its path is taken by the live Zahrada) puts it at `Pages/Zahrada (2).md` and says `Restored "Zahrada" as "Pages/Zahrada (2).md"`; the live Zahrada is untouched. Restoring a folder row moves the folder back in one rename (D-225: a type whose definition was trashed with it stays trashed; its objects show as Page per D-103 until the type is restored in Type settings). A trashed note whose original folder no longer exists is restored into a recreated folder. *(L4; L5)*
- **AC-6** **Open from the trash, read-only.** Activating a row's title opens `note/.trash/<path>` read-only (read view, no editor, the banner `This object is in the trash. Restore it to edit it.` with `Restore`); nothing is written, title edits are impossible (D-391 unchanged). Image rows show the image (R76). *(L5)*
- **AC-7** **Delete permanently (AP-535, T1).** `Delete "Hotovo" permanently…` (or ⌘⌫ on the focused row) asks R78's dialog (`Delete` / `Cancel`, Cancel default); `Delete` moves `.trash/Tasks/Hotovo.md` into the macOS Trash (`NSFileManager trashItemAtURL`), so it leaves the vault but can be recovered from Finder; Cancel and Esc do nothing. For T3 both files of the pair go. Tegg never unlinks a vault file itself. *(L4 against a temp vault and the user's Trash in L6 only; L5)*
- **AC-8** **Empty trash.** `Empty trash…` asks `Empty the trash?` with the count of rows; confirming moves every entry under `.trash/` (the folder's content, not `.trash/` itself) to the macOS Trash and shows the empty state; a file that can't be moved is left and the alert lists how many weren't removed. *(L4; L5)*
- **AC-9** **Keyboard and strings.** Rows are a list: ↑↓ move the focus, ↩ opens, R restores, ⌘⌫ asks to delete; Tab reaches `Empty trash…` and each row's buttons. Every text of R70 is an R78 key (pseudo-locale check); FR-UX-05 AC-4, AC-5 and axe `color-contrast` pass on `trash` with rows, with a dialog open and empty, light and dark. *(L1; L5)*
- **AC-10** **Nothing only in the index (AR-01).** The trash list, the trash times and the restore targets come from the file system: after deleting the index and reopening, AC-4's list is identical. *(L4)*
