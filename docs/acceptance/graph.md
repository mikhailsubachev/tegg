# Acceptance Criteria: Local graph, core and full view (v1.0 slice G1)

See [README](README.md) for conventions. Release v1.0 (BRD §11), slice **G1 "Graph core and full view"** (D-919; plan `docs/plans/v1-local-graph-plan.md` §3), the second graph slice after slice P (object previews, [previews.md](previews.md)). G1 builds the neighbourhood query in `tegg-index` (D-911), its d3-force layout (D-913), the full-view route `graph/<path>` (D-914) with the filter column, the canvas and the preview column, the empty, loading, too-many and deleted states, and live updates. The graph only reads: it writes nothing to the vault, ever; its view state is machine-local (`ui-state.json`, D-906). Exit goal: from any object the owner opens its neighbourhood as a full view, filters it by type and connection, and previews and opens what is near it.

**Status: approved, 2026-10-29.** The owner accepted AP-827…AP-850 (end of this file) as proposed: D-970…D-993 (BRD v1.111). Contract: `docs/contracts/v1-graph.md`; ADR 0004 (`docs/adr/0004-graph-layout-d3-force-svg.md`).

**Scope.** FR-GRP-01 (the full view; the right panel's Graph tab is G2), FR-GRP-02 without presets, FR-GRP-03, FR-GRP-05, FR-GRP-06, FR-GRP-07, FR-GRP-08, the graph part of FR-TAG-05, NFR-PERF-11, and G1's checks of AR-01, FR-SYN-06, FR-UX-03, FR-UX-05, NFR-OTH-02 and the Reduce-motion part of FR-UX-08 that D-913 names. **Out of scope** (see [Seams](#seams-what-g1-leaves-for-g2-and-g3)): the panel's Graph tab, its depth and filters popover, its 60-node cap and its preview popover, panel → full view, FR-NAV-05 (G2); filter presets and `.tegg/graph.yml`, the keyboard map, VoiceOver reading, the List view, hover mode and Off in the graph, FR-UX-03 / FR-UX-08 beyond what is listed here, FR-LNK-12 in the graph (G3); the global graph (FR-GRP-04, v1.x); tabs (FR-NAV-06, D-970).

**Risk tiers** (test-strategy §3). G1 writes nothing, so its T1 risk is a write it shouldn't make (FR-SYN-06 AC-38). Its main risk is **T2, silently wrong data**: a missing or extra edge, a wrong depth, a node from `_templates/` or `.trash/`, a filter that hides more than it says, or a stale graph after an external change. Those criteria have exact node and edge sets from the fixture.

### R108. Edges (FR-GRP-01, FR-GRP-02; D-900…D-902, board `Graph` `STY`)

| Kind (toggle label) | What makes it, from either object | Line (board `Graph`) | Strength (D-902) |
| --- | --- | --- | --- |

- **Not edges** (D-900): unresolved links, dates without a Daily Note (no ghost nodes), links from an object to itself (also through its own attachment, `file:`), anything in `_templates/` (FR-TPL-07) or `.trash/` (D-102); plain date values and `icon` / `cover` (D-971, D-972).
- **One edge per pair** (D-902): every way two objects are joined is one line in the style of the strongest **visible** kind (D-973); no arrowheads. Colour `--edge`; the selected node's edges `--hl`.
- Every edge whose two ends are drawn is drawn, also when one end is a leaf (Tag node or Daily Note) (D-974).

### R111. The cap (FR-GRP-01; D-912; D-978)

1. Count the filtered walk at this depth (`total`, the centre included). If `total` ≤ 150, draw it all.
2. Otherwise keep the centre and every depth-1 node (if depth 1 alone is above 1,000, its 1,000 most connected by rule 3).
3. Fill the remaining places depth by depth (2, then 3); within a depth, by vault-wide degree descending, then by sort key in NFC code-point order: the path for objects, `tag:<key>` for tag nodes. A node is eligible only if a neighbour one step closer to the centre is kept, so no kept node is cut off.
4. `Show all` draws the whole walk when `total` ≤ 1,000; it is offered only when rule 3 dropped nodes.

### R118. `.tegg/graph.yml` (FR-GRP-02, FR-STO-06; D-906, D-907; AP-920…AP-923, AP-926, AP-945)

**Format** (as `tests/fixtures/graph-presets/valid.yml`; versioned like `.tegg/types/*.yml`, AR-07):

```yaml
# Tegg graph filter presets (FR-GRP-02, D-906, D-907). Edit them in the graph's Preset menu.
version: 1
presets:
  - name: Bez štítků
    hidden-types: [tag, kniha]
    hidden-kinds: []
  - name: Jen vztahy
    hidden-types: []
    hidden-kinds: [link, embed, tag]
```

| Key | Rule |
| --- | --- |
| `version` | positive integer; missing reads as 1 (as D-235); 1 is current; > 1 → read-only (AP-923); `0`, a string, a non-integer → the file is unreadable |
| `presets` | a list; missing reads as no presets; anything else → unreadable |
| `name` | a string, compared after NFC and trimming, case-insensitively (D-907); shown as written (NFC) |
| `hidden-types` | a list of type keys (strings); missing = `[]`; unknown keys are kept and ignored (D-907, D-977) |
| `hidden-kinds` | a list of `link`, `relation`, `embed`, `tag`; missing = `[]`; other values are kept and ignored |
| anything else | top-level and per-preset unknown keys and every comment are kept byte for byte (FR-FMT-07) |

**Read rules** (AP-922): the file is read as UTF-8 YAML; invalid YAML, invalid UTF-8, a top level that isn't a mapping, a bad `version` or `presets` → **unreadable**: the menu lists only `Default` and never rewrites the file. Within a readable file an entry is **skipped** (not listed, kept byte for byte) when its `name` is missing, not a string, or blank after trimming; when it equals `Default` (case-insensitive); when it duplicates an earlier listed name (NFC, case-insensitive); or when `hidden-types` or `hidden-kinds` isn't a list of strings. Listed presets keep the file order (AP-945). Only the exact path `.tegg/graph.yml` is read; sync conflict copies (`graph 2.yml`, `graph (conflicted copy …).yml`) are never read, written or deleted (AP-925).

**Write rules** (AP-921), one atomic write per user action (FR-SYN-02), with the version last read as base (FR-SYN-03 AC-22): `save` appends one item after the last line of the `presets` list (or replaces `presets: []`, or adds `presets:` at the end) with the existing items' indentation (else 2 / 4 spaces); `update` rewrites only that item's `hidden-types` and `hidden-kinds` values as one-line flow lists, keeping a trailing ` # comment` on the line; `rename` rewrites only that item's `name` value; `delete` removes the item's lines (from its `- ` line to the line before the next line indented at most as far as the dash); deleting the last item leaves `presets: []` (AP-926). Values are written plain when YAML reads them back unchanged, else double-quoted (the `vault.yml` rule, D-230). Lists are written with the vault's types in the D-977 order, then unknown keys in their previous order; kinds in the order `link, relation, embed, tag`. Names are written NFC. A missing `version` is written as `version: 1` after the header comments on the first write. Line endings follow the file (CRLF stays CRLF); a missing final newline stays missing. A new file is `tests/fixtures/graph-presets/expected/created.yml`'s shape: the header comment line, `version: 1`, `presets:` and the item. **`Default` is never written.** Nothing writes the file except `save`, `update`, `rename`, `delete` (D-906); an operation that leaves the bytes equal writes nothing.
