# Acceptance Criteria: Block → object conversion and the Task card (MS5 slice 5A-2, D-500)

See [README](README.md) for conventions. Milestone MS5 (BRD §11.2), slice **5A "Tasks and conversion"** (`docs/plans/mvp-daily-use-plan.md` §3 row 3; D-08, D-27, D-28, D-74). Any block, or a run of blocks, of the open note can be turned into an object of a chosen type: the first line becomes its title, the rest its body, the object is saved as its own file with `source` pointing back, and the blocks are replaced by an embed of it (`![[…]]`, 4F's embed vocabulary: [embeds.md](embeds.md), `docs/contracts/ms4-embeds.md`). Converting a checklist item into a Task takes one action (FR-TSK-11). The Task embed becomes the **D-74 card**: a header row with checkbox, title, status, priority, due date and open button, and the task's body below it, editable in place. A conversion writes exactly two files: the new object (create-exclusive) and the source note (through its editor); it is one undo step, not a `tegg-jobs` job and not a restore-point operation (FR-HIS-04 covers bulk and destructive operations). The Tasks page, statuses, quick-add and the Daily Note section are in [tasks.md](tasks.md), whose fixture, test clock and layers this file uses.

### R51. What becomes title and body (FR-CNV-02, -03; AP-420, AP-421, AP-425)

| First selected block | Title | Rest of that block | Note |
| --- | --- | --- | --- |
| Paragraph | its first line as plain text | its other lines, as a paragraph | |
| Heading | its text | — | |
| List or checklist item | its first line without the marker (`- `, `1. `, `- [ ] `, `- [x] `) | its other lines and its nested items, de-indented by the item's content offset | a checked item converted to a Task gets the first Done-state status and `completed` (AP-425) |
| Quote, callout | the first line of its text (without `> `, without the `[!type]` line for a callout) | the rest of the quote or callout, as a quote / callout | a selection inside a quote or callout extends to the whole quote or callout (AP-420) |
| Code block, table, divider, embed, source block, placeholder | empty (the user types one) | the whole block, verbatim | |

- **Plain text of the first line (AP-421):** formatting markers dropped (`**nový**` → `nový`), a link becomes its alias or the target's title (`[[Zasedačka]]` → `Zasedačka`), trailing `#tag` tokens are removed from the title and written to `tags:`; NFC; leading and trailing spaces trimmed. When the first line held a link, the line as written (marker and trailing tags removed) is also kept as the body's first paragraph, so no link is lost.
- **Body:** the remaining selected blocks follow in order, each byte for byte (top-level list items the selection spans after the first stay list items with their markers), separated by one blank line where they weren't neighbours; lines are written with `\n` (a new file is canonical, dialect §2); the body ends with one `\n`, or is empty.
- **Embed in the source (FR-CNV-03; AP-420):** the selected top-level blocks are replaced by one paragraph `![[<D-184 target of the new object from the source>]]`, separated from its neighbours by one blank line. A run of items in a list is cut out of the list: the items before stay one list, the embed paragraph follows, the items after form a second list with their bytes unchanged (a numbered list keeps its numbers: `3. Třetí bod` stays `3.`). A nested list item converted on its own is replaced in place by a nested item whose only content is the embed (`  - ![[…]]`), which 4F shows in link mode (D-419). The file's other bytes, line endings (CRLF stays CRLF on new lines too, editor.md FR-FMT-07 AC-12), BOM and final newline state are unchanged.

If the source's save then fails or gets `Conflict`, the editor keeps the converted state unsaved and follows editor.md's failure and merge rules (FR-EDT-08 AC-11, FR-SYN-03 AC-13); the new file stays. *(L5 for the order and counts; L4 for the create)*
