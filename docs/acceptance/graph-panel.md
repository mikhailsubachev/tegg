# Acceptance Criteria: Local graph in the right panel (v1.0 slice G2)

See [README](README.md) for conventions. Release v1.0 (BRD §11), slice **G2 "Graph in the panel"** (D-919; plan `docs/plans/v1-local-graph-plan.md` §3), after G1 ([graph.md](graph.md), the query, layout and full view) and slice P ([previews.md](previews.md)). G2 turns on the right panel's Graph tab (FR-NAV-05), with a depth and filters popover, the 60-node panel cap (D-912), the node preview as a popover beside the panel (D-917), the way from the panel to the full view (D-905), the palette command `Show local graph` (D-918) and the panel's empty, loading, too-many and deleted states. Like G1 it only reads: it writes nothing to the vault; its view state is machine-local (`ui-state.json`, `graph.panel`, D-906, D-993). Exit goal: on any note the owner sees what is linked to it beside the text, filters it, previews a neighbour without leaving the note, and moves to the full view in one step.

**Status: approved, 2026-10-30.** The owner accepted AP-880…AP-893 (end of this file) as proposed: D-1030…D-1043 (BRD v1.116). Contract: `docs/contracts/v1-graph.md` §15.

**Scope.** FR-GRP-01 (the panel part), FR-GRP-02 (the panel's filters, without presets), FR-GRP-03, -05, -06, -07, -08 in the panel, FR-NAV-05 (the Graph tab; the D-920 change of AC-1 in [inbox.md](inbox.md)), NFR-PERF-11 for the panel, and G2's checks of FR-SYN-06, FR-UX-03, FR-UX-05, NFR-OTH-02 and Reduce motion (FR-UX-08, D-913). Reference tables R114…R117. **Out of scope** (see [Seams](#seams-what-g2-leaves-for-g3)): filter presets and `.tegg/graph.yml`, the keyboard map inside the graph, VoiceOver reading, the List view and the `Graph` / `List` switch, hover mode and Off in the graph (G3: G2 keeps click mode in every setting, D-983); the global graph (FR-GRP-04, v1.x); tabs (FR-NAV-06; "opens in a new tab" means the current view with a new history entry, D-970).

**Risk tiers** (test-strategy §3). G2 writes nothing, so its T1 risk is a write it shouldn't make (FR-SYN-06 AC-39). Its main risk is **T2, silently wrong data**: the panel showing another object's graph after a navigation, a stale graph after an edit, a cap that draws a partial neighbourhood as if it were whole, or panel and full-view state bleeding into each other. Those criteria have exact node sets from the fixture.

**Test layers:** as in [graph.md](graph.md) (L0, L1, L2, L4, L5, L6, manual); G2 adds no layer and no IPC command. L5 uses the G1 fake core (v1-graph §8), whose `graphCalls()` records every request with its `cap`.

**Test clock** (L5, L6 with `TEGG_TEST=1`): as graph.md (`2026-10-28T10:00:00+01:00`, Europe/Prague, region `en-US`, Object preview *Click to preview*, `ui-state.json` without a `graph` entry), plus `rightPanel: { open: true, tab: 'graph', width: 288 }`. Window 1,440 × 980 with the sidebar open (232 px), so the panel is 288 px and its canvas 260 px wide (R114), unless a criterion says otherwise. Each criterion names a suggested test name (`Test:`); a test may split a criterion into several tests with the same prefix.

**Fixture:** `tests/fixtures/vaults/graph/` unchanged, with its short names (graph.md "Fixture"), its runtime files and the hub; the panel's expected counts are in its README, section "Panel (G2)". No new fixture file. The benchmark (NFR-PERF-11 AC-3) uses the reference vault (`tools/gen-vault --seed 1`).

### R116. The 60 cap and the way to the full view (FR-GRP-01; D-905, D-912; D-1033, D-1034, D-1036, D-1037)

1. The panel asks `graph_neighbourhood` with `cap: 60`, `showAll: false` and the panel's depth and filters (v1-graph §15). If the result's `total` (filtered walk, centre included) is above 60, the panel draws nothing and shows Too many (R115); otherwise it draws the whole result (`truncated` is then false).
2. **Lower depth offered:** the deepest depth `d'` below the current depth with `depthTotals[d'−1]` ≤ 60, as `Depth <d'> · <depthTotals[d'−1]>`; none when no lower depth fits (at depth 1, or depth 1 above 60). Choosing it sets the panel's depth (stored).
3. **To the full view** (`Open full view`, `In full graph`, and ⌘⇧G / `Open graph` while the panel shows the Graph tab): `graph/<centre path>` as a new history entry (D-970), at the **panel's current depth**, with the node selected in the panel (if any) selected in the full view and previewed in its column; the full view's filters and size come from `graph.full` (filters are not copied, board `GraphPanel` "Panel → full view"). The hand-over lives on that history entry (Back and Forward show it again); it writes nothing to `graph.full` (D-1037).
4. Without the panel on the Graph tab (panel closed, another tab, or a route without the panel), ⌘⇧G and `Open graph` work as G1 (FR-GRP-01 AC-11: the full view's own depth, no selection).
