# Acceptance Criteria: Performance

See [README](README.md) for conventions.

## Reference setup (AP-8, D-58)

- **Machine:** Apple M1 with 8 GB RAM (the slowest supported Apple Silicon), macOS 14, release build, no other heavy apps running. Results on faster Macs are reported but don't count.
- **Reference vault:** generated by `tools/gen-vault` with a fixed seed, so every run is identical:
  - 5,000 notes: 60% short (50–300 words), 35% medium (300–2,000 words), 5% long (2,000–5,000 words); Czech and English text with diacritics.
  - 12 types, 40% of notes with 3–8 attributes; 3–10 links per note, 15% with embeds; 200 tags.
  - 2,000 images (100 KB–3 MB) in `_attachments/` with Image objects.
- **Measurement:** each metric is the **95th percentile** of at least 20 runs, measured by automated benchmarks unless marked [manual]. Benchmarks run on every release candidate; a regression of > 20% fails the build.

| ID | Metric | Target | How it's measured |
| --- | --- | --- | --- |
| NFR-PERF-01 | Cold start to usable UI | < 2 s | Launch after reboot cache flush → sidebar and Home rendered and accepting input (index already built) |
| NFR-PERF-02 | Initial full index | < 30 s | Open reference vault with no index → index complete; during indexing, typing in an open note stays within NFR-PERF-06 |
| NFR-PERF-03 | Quick switcher | < 100 ms per keystroke | Keystroke → results list rendered, for 1–10 character queries incl. diacritics-insensitive matches |
| NFR-PERF-04 | Full-text search | < 200 ms | Query submitted → first 50 results with snippets rendered; single words, phrases, and a filter by type |
| NFR-PERF-05 | Open a note | < 150 ms | Click in switcher → content rendered and editable, for a 5,000-word note with 10 embeds |
| NFR-PERF-06 | Typing latency | < 16 ms | Key event → glyph painted, in a 5,000-word note, while the index updates in the background |
| NFR-PERF-07 | Query view, 1,000 results | < 300 ms | Open a table view of 1,000 objects → visible rows rendered; scrolling stays at 60 fps (virtualized) |
| NFR-PERF-08 | External change reflected | < 2 s | File changed by another process → index, open note and visible query views updated |
| NFR-PERF-09 | Memory, idle | < 400 MB | Total of all app processes (Rust core + WebView) 60 s after opening the reference vault with one note open |
| NFR-PERF-10 | Quick Capture open | < 300 ms | Global hotkey → capture window visible with cursor in the text field, with the main window **closed** |

### Additional criteria

- **NFR-PERF-02/AC-2** Re-opening a vault with an existing index whose files changed while the app was closed (100 changed files) updates the index in < 3 s.
- **NFR-PERF-03/AC-2** The quick switcher keeps < 100 ms with a 20,000-note generated vault (headroom check; reported, not a release blocker).
- **NFR-PERF-06/AC-2** [manual] No visible stutter while typing during a full re-index.
