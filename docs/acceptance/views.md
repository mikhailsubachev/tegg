**Risk tiers** (test-strategy §3). This slice **writes vault files** in four new ways:
- the type file's `views:` line (tab drag, add, remove; the rename job);
- the query files' `sort`, `lanes`, `lane_order`, `group_by`, `view`, `columns` (sort popover, header click, lanes switch, lane drag, Reset lane order, the editor);
- an object's attribute on a **card drag**;
- new objects from a lane.

So its top risk is **T1, data loss**: a card drag that rewrites more than the one attribute, drops another value of a multi-value attribute, edits an inline tag in the body, or overwrites an external change; a `sort` or `lane_order` write that drops comments or unknown keys or rewrites a file Tegg can't read; a `views:` write that loses a tab name or rewrites the type file's other lines; a rename that misses a `views:` entry. Those criteria are marked **(T1)** and check bytes, mtime and inode. Next is **T2, silently wrong data**: a card in the wrong lane or in no lane, a missing lane, a wrong sort order between levels (ties, Czech collation, empty values, option order), a hidden card counted, a trashed or template object as a card, NFC/NFD names that split a tab or a lane. Those are marked **(T2)** and are checked against fixed expectations and the brute-force oracle of FR-QRY-02 AC-8.

### R184. `views:` in the type file (FR-QRY-07, AR-07; D-1762; AP-1498)

```yaml
preview: [author, status]
columns: [author, rating, status, modified]
views: [Rozečtené, Přečtené 2026, Výborné knihy]
```

| Rule | |
| --- | --- |
| Meaning | the view tabs after `All <plural>`, in order. A missing key means only `All <plural>` |
| Names | resolve as `saved:` does (D-1434, D-1475): NFC, case-insensitive name match; written NFC, in the D-230 style (plain when YAML reads the name back unchanged, else double-quoted, e.g. `"Čtu, až bude čas"`) |
| Place (AP-1498) | TOP order `… preview, hidden, columns, views, embed, template, attributes` (D-1812); a missing key is inserted at that place on the first tab change |
| Shape (AP-1498) | a flow list; a hand-written block list is read and replaced by one flow line on the next change; once written the key stays (`views: []` after the last removal); never written in new, starter or built-in type files |
| Odd values (AP-1498) | a repeated name (also in another case or NFD) shows one tab, at its first place, and `Remove` removes every copy; a name that resolves to no query shows a tab in R141's not-found state; a value that isn't a list leaves only `All <plural>`, `Add view` aria-disabled with the reason `The views setting in .tegg/types/<key>.yml can't be read. | Version (AR-07) | an optional key of version 1; `CURRENT_VERSION` stays 1 (as `columns`, AP-1149) |

### R185. Query-file keys added by Q2 (R138 additions; D-1768…D-1770; AP-1499, AP-1508)

| Key | Rule |
| --- | --- |
| `view` | `list`, `table` or `board`; any other value is a broken part (default `list`) |
| `group_by` | an attribute key of the query's single type whose kind is Select, multi-select, relation, or `tags` (D-1770). Any other key or kind is broken: the view is drawn as a List with `The setting group_by can't be read, so its default is used.` (D-1442). Read only with `view: board`; kept and ignored with `list` or `table` |
| `lanes` | `vertical` or `horizontal`; missing = `vertical`; any other value is broken (default `vertical`) |
| `lane_order` | a list of lane values (option labels, tag keys, or relation link text `"[[…]]"`, AP-1508); lanes not listed follow in the default order of R187; a listed value with no lane is kept in the file and ignored; not a list → broken (default order) |
| `sort` | a list of `{ by, order }` mappings, one per level, or R138's single mapping (one level). A missing `order` is `asc` (D-1462). A level whose `by` is not `title`, `created`, `modified` or an attribute, or an item that isn't a mapping, makes the whole `sort` broken (default `{ by: modified, order: desc }`) and the file isn't rewritten. A key used twice counts at its first level. Ties after the last level: title (D-122), then path |
| `columns` on a board | the `On cards` attributes, in order (board C); keys as R130 |
| `limit` on a board | not applied: every lane holds all its cards (plan §3); kept in the file |
| `version` | stays 1 (D-1768). An older Tegg reads a list `sort` as broken and keeps the file (D-1442) |

**Write style** (D-1436, D-1457, AP-1499). A commit replaces only the lines of the top-level keys whose value changed.
- `sort` with **one** level is written as R138's single mapping `sort: { by: title, order: asc }`; with **two or more** as a block list of flow mappings, one per line (board F):
  ```yaml
  sort:
    - { by: finished, order: desc }
    - { by: rating, order: asc }
  ```
- A trailing comment on a single-line `sort:` that becomes a list stays on the `sort:` line (`sort:   # jedna úroveň`); a list that becomes one level keeps the comment of its `sort:` line (AP-1499).
- `lanes`, `group_by`, `view` are plain scalars; `lane_order` and `columns` flow lists (D-230 quoting).
- A missing changed key is inserted at its place in the create order (D-1457), which becomes `… sort, limit, view, group_by, lanes, lane_order, columns, created, modified` (AP-1499).
- `Reset lane order` removes the `lane_order` line (or block) (AP-1508).
- Each change sets `modified:` (R138) and is one write, refused on an external change (FR-SYN-03).

**Create** (`New view`, AP-1497, AP-1499): R138's create order with the new keys. A Board view writes `group_by` (the first Select attribute in schema order, else the first multi-select, else `tags`), `lanes: vertical` and no `lane_order`; its `columns` are the type's `preview` keys without the grouping key. Table and List views write no board keys; their `columns` are the R130 effective columns of the type.

**Risk tiers.** Q2.1 moves writes from query files into **type files and notes**, which hold far more of the user's data:

### R195. Usage settings in a fence (FR-FMT-06; D-1836; AP-1519, AP-1520)

````markdown
```query
saved: Přečtené 2026
sort: { by: title, order: asc }
columns: [author]
```
````

| Rule | |
| --- | --- |
| Keys | `sort` and `columns`, top-level keys of the fence body (column 0 after any container prefix), with R185's values and read rules. `saved:` stays the reference (R140). Every other line (comments, unknown keys such as `x-poznámka`, `view:`, `filters:`) is kept byte for byte and ignored (R140) |
| Write style | as R185: `sort` with one level `sort: { by: title, order: asc }`, with two or more `sort:` then one `  - { by: …, order: … }` line per level; `columns` one flow line; D-230 quoting; NFC |
| Place (AP-1519) | a present key is replaced in place (its line or its block of lines, R185's range rules). A missing key is inserted after `saved:`, in the order `saved`, `sort`, `columns` (after `sort` when it is present). Removing an own value (R197 `Use the query's …`) removes its line or block |
| Bytes kept | the fence markers (```` ``` ```` or `~~~`, their length), the info string as written (`query meta`), the `saved:` line, container prefixes (`> `, list indentation; new lines get the prefix of the `saved:` line), the note's line endings and every byte outside the replaced lines |
| How it is written (AP-1520) | through the open editor: one transaction (`QueryCtl.setSource`, v1-queries §3.2), one undo step, one autosave (FR-EDT-08) whose `modified:` follows D-55; nothing else of the note changes |
| Where it can't be written (AP-1520) | a block with no editor of its note (the read view, a note in the Trash view, a block inside an embedded note): its sort button, header clicks, ⇧-clicks, header drags and `Columns` are `aria-disabled` with `Open the note to change how this block shows.`; resizing still works (machine-local) |
| Earlier fences | a reference fence written before 0.5.0 by hand with `sort:` or `columns:` lines now uses them (R140 ignored them) |

### R196. Usage settings in `views:` (R184 additions; AR-07; D-1836; AP-1521)

```yaml
views:
  - Rozečtené
  - name: Přečtené 2026
    sort:
      - { by: rating, order: asc }
      - { by: title, order: asc }
    columns: [author, rating, finished, genres]
  - Výborné knihy
```

| Rule | |
| --- | --- |
| Items | a name (a string, as R184) or a mapping with `name` (a non-blank string, resolved as R184) and optional `sort` and `columns` (R185 values). A mapping without a string `name` makes the whole `views` unreadable (R184 odd values). Other keys of an item are kept and ignored |
| Write style | while every item is a plain name: R184's one flow line. When any item has own settings: a block list, `  - <name>` for plain items and `  - name: <name>` followed by `    sort: …` and `    columns: […]` (that order; a multi-level `sort` as `    sort:` and `      - { by: …, order: … }` lines) for the others. The write switches back to the flow line when the last own setting goes |
| Minimal rewrite | a `views` write replaces the key's lines. An item whose value didn't change keeps its own lines byte for byte (as `filters` items, D-1436), its unknown keys and comments included; a changed item is re-emitted with its unknown-key lines kept after the known ones; full-line comments between items go (AP-1521) |
| Repeats | a name listed twice (any case, NFD) is one tab with the **first** item's settings; `Remove` removes every copy (R184) |
| Version | an optional shape of version 1; `CURRENT_VERSION` stays 1. Tegg 0.4.0 reads a mapping item as an unreadable `views` (only `All <plural>`, no write) (AP-1521) |

### FR-QRY-07 Views per type (part two)

- **AC-19** **Menus and popovers stay inside the window (F1, bug; D-136; AP-1529).** At each window size 800 × 500 (the minimum, D-136), 1,024 × 768, 1,440 × 900 and 2,560 × 1,440, with the sidebar open and collapsed, each of these opens fully inside the window: the toolbar `⋯` `View actions` on `Přečtené 2026` and on `Rozečtené` (with `Reset lane order`); the tab menu from the chevron of the last tab, from a right-click on it and from ⇧F10; the `Add view` menu; the sort popover from the toolbar and from Čtení's block header; the `Columns` menu on a tab and in a block; `More actions` and its `Move to` submenu on the last card of the rightmost lane of a runtime `Podle autora` tab; the editor (`Edit view` from a tab, `Edit query` from a block; D-1864). "Inside" means: the popup's bounding box lies within 8 px of every window edge (left ≥ 8, top ≥ 8, right ≤ width − 8, bottom ≤ height − 8, ± 0.5 px); each of its items or controls, scrolled into view inside the popup, is the element `elementFromPoint` returns at its centre (no ancestor clips it, the board's sideways scroller included); the page gets no horizontal or vertical scroll from it. Placement: below the opener, left-aligned with it; when its right edge would pass width − 8 it is right-aligned with the opener's right edge (opens leftwards), then clamped to the 8 px margins; when it doesn't fit below it opens above the opener, and when it fits on neither side it goes on the side with more room with its height limited to that room, scrolling inside. A context menu does the same from the pointer. A submenu opens to the right of its item, else to its left. With Čtení scrolled so its block header is 40 px above the window's bottom, the block's sort popover opens upwards.
