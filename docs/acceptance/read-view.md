# Acceptance Criteria: Read view (MS3 slice 3B)

See [README](README.md) for conventions. Milestone MS3 (BRD §11.2), slice **3B "Read view"** (D-115, D-117; plan `docs/plans/ms3-implementation-plan.md` §3). The note route stops showing the raw file and shows it **formatted and read-only**: blocks, inline formatting, clickable `[[links]]` and `#tags`, frontmatter as a read-only attribute strip, and a source view toggle. Slice 3C replaces the rendered body with the editor; the read view stays as the view for files the editor can't open safely (NFR-REL-03, D-117).

**Status: accepted, 2026-10-13.** Writing these criteria raised AP-84…AP-95 (end of this file); the owner accepted all proposals as D-140…D-151 (BRD v1.28). A criterion that cites an AP follows its decision.

**Scope.** FR-EDT-10 (source view), FR-EDT-02 (block and inline types, display only), FR-TYP-08 (universal attributes, display only), NFR-PERF-05 (open a note, the read-view part), plus the MS3 parts of NFR-REL-03, FR-SYN-03 and FR-SYN-06 that the read view makes verifiable. Editing, previews (FR-LNK-08…13, v1.0), embeds (FR-EMB, MS4), backlinks (MS4), images (FR-ATT, MS6) and the attribute panel (FR-EDT-07, 3D) are out of scope; where the read view meets them it shows a placeholder (table R5).

**Test layers** as in [app-shell.md](app-shell.md): L1 Vitest (the renderer as a React component in a DOM environment, fed with file text), L4 Rust core, L5 Playwright on WebKit with the fake core, L6 Appium on the built app, manual.

### FR-EDT-10 Source view toggle (read-only)

- **AC-1** **Toggle.** On a `note/<path>` route, the note toolbar's toggle button `Show Markdown source` (`aria-pressed` false) and the shortcut `⌥⌘U` (AP-90) switch the centre pane to the source view; the button then reads `Show formatted note` (`aria-pressed` true) and the same button or shortcut switches back. The palette has the command `Toggle Markdown source` with that shortcut; on routes without a note it isn't run (it shows no error and changes nothing). *(L5)*
- **AC-2** **Exact text.** The source view shows the file's text exactly as `note_read` returned it, including frontmatter, CRLF line endings (shown as line breaks), trailing spaces, tabs, a BOM-less first line, NFD sequences, HTML and `%%comments%%`: the concatenated text of its line elements, joined with `\n`, equals the file text with CRLF replaced by LF and a leading U+FEFF removed. Tested on Bloky, Vlastnosti, Chyba tabulátor and a test-written CRLF copy of Odkazy. *(L1)*
- **AC-3** **Read-only and selectable.** In the source view nothing is editable (no `contenteditable`, no `textarea`, no `input`); text can be selected with the keyboard and the pointer and copied with ⌘C, and the clipboard then holds the selected source text. Typing, paste (⌘V) and ⌫ change nothing and send no IPC command. *(L5)*
- **AC-4** **Line numbers.** Each line shows its 1-based line number in a gutter that is excluded from selection and copy (AP-90). *(L5)*
- **AC-5** **Not remembered (AP-90).** Each note route opens in the formatted view (except the files of NFR-REL-03 AC-3); switching to another note and back, or relaunching, shows the formatted view again. Toggling writes nothing to the vault and nothing to the Application Support root. *(L5; L6 for relaunch)*
- **AC-6** **Position kept.** Given Cíl is scrolled so that the heading `Druhá kapitola` is the first visible block, switching to the source view shows that heading's source line within the visible area, and switching back shows the heading within the visible area again. *(L5)*
- **AC-7** **No links in the source view.** In the source view, `[[…]]`, `#tags` and URLs are plain text: they aren't links or buttons and clicking them doesn't navigate. *(L5)*
- **AC-8** **Same theme quality.** The source view uses the monospace font of the code blocks and only theme tokens; FR-UX-05 AC-4 and AC-5 (axe `color-contrast`, no colour leaks) pass on Bloky in the source view in light and dark. *(L5)*

### FR-EDT-02 Block and inline types (display only, slice 3B)

All criteria render the fixture notes in the formatted view. "Is rendered as" means the element and accessible role named, inside the note body `article` (accessible name = note title), in file order. No block of the body is lost: every block of `@tegg/doc` `parse(text).blocks` produces at least one element, and its text content (minus markup) appears in the view (AC-12).

- **AC-1** **Headings.** In Bloky, ATX `#`, `##`, `###` and the Setext heading are rendered as `h2`, `h3`, `h4` and `h2` respectively (the note title is the page's only `h1`, FR-UX-02 AC-14); `####`…`######` are rendered as `h5`, `h6`, `h6` (AP-93). Each heading has an id derived from its text so it can be a link target (AC-7). *(L1)*
- **AC-2** **Lists and checklists.** Bulleted lists (`-`, `*`, `+`) are `ul`, numbered lists (`1.`, `1)`) are `ol` starting at the written start number (`3.` starts at 3); nesting (two levels) is kept as nested lists. Checklist items `- [ ]`, `- [x]`, `- [X]` are list items with a `checkbox` role, checked for `x`/`X`, with `aria-readonly="true"`; clicking or Space on one changes nothing, sends no IPC command and writes nothing (FR-TSK-11 editing is 3C/MS5). *(L1 for structure; L5 for click)*
- **AC-3** **Quotes and callouts.** A `>` quote is a `blockquote`. A callout `> [!warning] Pozor` is a `note`-role block (not a `blockquote`) with a title `Pozor` and a type label from the catalog for the 13 Obsidian callout types (`note`, `abstract`, `info`, `todo`, `tip`, `success`, `question`, `warning`, `failure`, `danger`, `bug`, `example`, `quote`; aliases such as `caution` → warning as in Obsidian); an unknown type `[!budget]` renders as `note` with its raw type as the label. Without a title the callout shows its type label. A foldable callout `[!tip]-` starts collapsed and `[!tip]+` expanded; the fold toggle is a button that changes only the view and writes nothing. Each callout type uses a theme token colour (FR-UX-05 AC-2). *(L1; L5 for fold)*
- **AC-4** **Code, tables, dividers.** Fenced and indented code blocks are `pre > code` with their text exact (no Markdown inside is interpreted: `[[Kód]]` and `#kód` inside are text), the fence's language shown as a label; no syntax highlighting is required. A GFM table is a `table` with header cells `th` and its column alignments; `\|` inside a cell is shown as `|`, and a wikilink with `\|` alias in a cell is one link (dialect §4, §5). `---`, `***`, `___` between paragraphs are `hr`. *(L1)*
- **AC-5** **Inline formatting.** `*em*`/`_em_` → `em`, `**strong**`/`__strong__` → `strong`, `~~s~~` → `del`, `==h==` → `mark`, `` `c` `` → `code`, hard line breaks (two trailing spaces or `\`) → `br`. Inline `%%comment%%` and comment blocks are not shown. Inline `$x$` and block `$$…$$` math are shown as their source text in code style (AP-89); `$5 and $3` stays plain text (dialect §5). Footnote references and definitions are shown as their source text. A block id ` ^abc123` at the end of a block is not shown, and the block gets it as its element id (`^abc123`) for AC-7. *(L1)*
- **AC-6** **Wikilinks and Markdown links to notes.** Each of these in Odkazy is rendered as one link chip (D-73: object or type icon + display text, link colour, tint, regular weight) with role `link` and accessible name = display text: `[[Cíl]]` ("Cíl" title shown), `[[Cíl|jiný text]]` ("jiný text"), `[[Cíl#Druhá kapitola]]`, `[[Cíl#^blok1]]`, `[[cíl]]` (case-insensitive, dialect §6), a target written in NFD, `[text](Cíl.md)` and `[text](C%C3%ADl.md)` (URL-decoded). Display text without an alias is the target's `title`, else the link text (FR-LNK-07, D-73). Links resolve by the dialect §6 rules through the core (L4 checks the resolution; L1 the rendering for given resolutions): `[[Dvojník]]` in Odkazy (in `Pages/`) resolves to `Pages/Dvojník.md`, never by title alone (FR-LNK-14); aliases don't resolve: `[[Reading list]]` is unresolved (AP-85); templates and `.trash/` are never targets (FR-TPL-07, D-102). *(L1, L4)*
- **AC-7** **Following a link (AP-84).** Click, or ⏎ with the link focused, on a resolved link opens the target's `note/<path>` route, records it with `nav_opened` (D-138) and puts the focus on its title (FR-UX-03 AC-11). With a `#Heading` subpath the heading is scrolled into view 24 px below the note toolbar (± 8 px, D-1673), with `#^id` the block with that id; a subpath that doesn't exist opens the note at the top with no error. `[[#Úvod]]` inside a note scrolls within it and doesn't change the route. ⌘-click acts as a click (tabs are v1.0, FR-NAV-06). No preview popover is shown in 3B (FR-LNK-08 is v1.0). *(L5)*
- **AC-8** **Links that don't resolve (AP-86).** `[[Neexistuje]]` and `[[Reading list]]` are rendered with the broken-link style (D-73: no tint, error colour token, dashed underline) and the accessible description `No note named <target>` (catalog); activating them does nothing: no route change, no IPC write command, no file created (creating from a link is MS4, FR-LNK-04). A date link `[[2026-10-07]]` resolves to Denní; `[[2026-10-08]]`, with no Daily Note, is **not** shown as broken (FR-DLY-08) and is a disabled control with `Coming in MS4` (AP-86). *(L1 for style; L5 for activation)* *(From slice 4A, D-293: activating an unresolved link opens the Create offer of backlinks.md FR-LNK-04 AC-4 instead of doing nothing; the date-link part stays until 4B and shows `Coming in MS4 (4B)` (D-292). The test changes in the 4A build commit with `AC-Test-Change: 4A replaces D-142's broken-link behaviour; approved-by: owner`.)* *(From slice 4B, D-142 ends: `[[2026-10-08]]` keeps the date-link style (not broken) and activating it opens the virtual Daily Note `daily/2026-10-08` without writing (daily-notes.md FR-DLY-08 AC-5, AC-6); the `Coming in MS4 (4B)` disabled state is removed. The test changes in the 4B build commit with `AC-Test-Change: 4B replaces D-142's date-link placeholder; approved-by: owner`.)*
- **AC-9** **Tags (AP-87).** In Odkazy, `#projekt`, `#Projekt/alfa` and `#Čeština` written in NFD are rendered as tag chips with role `link`, accessible name `#<name>` as written; `#1`, `# Nadpis`, `site.com/#x`, `` `#kód` ``, `$#x$` and a `#tag` inside a link's text are not tags (dialect §5, D-64). Activating a tag opens the tag's page; until tag pages exist (FR-TAG-06, MS4) that is the `tags` route placeholder (D-218, supersedes D-143). *(L1 for detection; L5 for activation)*
- **AC-10** **External links (AP-89).** `[web](https://example.com/a?b=c)` and a bare `https://example.com` (GFM autolink) are links with the external-link icon; activating one asks the shell to open it in the default macOS handler (`open_external`), and the app itself makes no network request (NFR-SEC-01: the fake core and the WebKit network log show zero requests to non-local hosts during the whole test). `mailto:` opens the same way. Any other scheme (`javascript:`, `file:`, `data:`, `vbscript:`, unknown) is rendered as plain text with the URL shown, never as a link, and is never passed to `open_external`. *(L5)*
- **AC-11** **No HTML, no remote content (AP-89).** HTML blocks and inline HTML in Bloky (including `<script>`, `<img src=https://…>`, `<iframe>`, an `onclick` attribute and `<style>`) are shown as their source text in code style and never become DOM elements: after rendering, the note body contains no `script`, `iframe`, `object`, `embed`, `style`, `img` with a non-local `src`, or element with an `on*` attribute; no script from the note runs (a test global stays unset). Markdown images with remote URLs aren't loaded (R5 `embed-image`). *(L1; L5 for the network check of AC-10)*
- **AC-12** **Nothing lost, nothing invented.** For each fixture note and for 200 notes of the generated reference vault (seed 1, `--small-images`), rendering doesn't throw, and the normalized text content of the body (whitespace collapsed, markup and hidden comments removed) contains every word of the body text that isn't inside a comment, a block id or link/embed syntax, in order. Unknown fences (`dataview`) are code blocks (AC-4). *(L1)*
- **AC-13** **R5 placeholders.** Each row of R5 is rendered for its syntax in Bloky or Odkazy as a `region` named by the placeholder's catalog name, containing the shown parts of the "Also shown" column and `Coming in <milestone>` with the requirement IDs; the note embed's chip opens the note (AC-7). Rendering a placeholder sends no IPC command other than the batch link resolution (AP-88). *(L1, L5)*
- **AC-14** **Read-only.** In the formatted view no element is editable (`contenteditable`, inputs other than read-only checkboxes); typing, paste and ⌫ change nothing. A visible note in the toolbar says `Editing comes in MS3 (3C)` as a disabled control `Edit` (R3, until 3C). *(L5)*
- **AC-15** **Both themes.** FR-UX-05 AC-4 and AC-5 pass on Bloky, Odkazy and Vlastnosti in the formatted view, light and dark: callouts, chips, broken links, code, tables, marks and placeholders use only theme tokens. *(L5)*

### FR-TYP-08 Universal attributes (display only, slice 3B; AP-91)

- **AC-1** **Attribute strip (read view only; changed by D-242).** In the read view (files the editor can't open, and the read-view test switch, D-215), between the title and the body, Vlastnosti shows a `region` named `Properties` (the Main board's grid: label column, value column). It lists the attributes in this order: `description` is shown as the note's subtitle under the title, not in the strip; then `tags`, `aliases`, the other attributes in file order, then `source`, `review`, `created`, `modified`. Not shown: `id`, `type`, `title` (shown elsewhere), `icon`, `cover` (3E, FR-TYP-14), `import-id`, `previous`, `file` (shown on Image/PDF in MS6), empty values (`key:`, `null`, `~`, `[]`) (AP-91). On the editor route the panel's order of types.md FR-EDT-07 AC-1 applies instead. *(L1)*
- **AC-2** **Labels.** Reserved keys use catalog labels (`Tags`, `Aliases`, `Source`, `Review`, `Created`, `Modified`, `Description`); any other key is shown exactly as written in the file (user content, NFC), e.g. `stav`, `počet`. A date range pair `cesta-start` / `cesta-end` is shown as one row `cesta` with both dates (FR-TYP-02). *(L1)*
- **AC-3** **Values by format** (dialect §3): text as text; numbers as written; `true`/`false` as a read-only checkbox; a date `2026-10-20` and a date-time `2026-10-07T14:30:00+02:00` formatted with the region locale (`Intl.DateTimeFormat`, medium date; date-times in the machine's zone, D-104), the date never shifted by a time zone (FR-FMT-11); `tags` as tag chips (AC-9 activation); `source` and relation values `"[[Cíl]]"` as link chips (AC-6, AC-7 behaviour); lists as a row of chips or comma-separated values; `review: unreviewed` as the catalog label `Unreviewed`; a nested map or other value the formats don't cover as its YAML source text in code style. The date and time format setting (FR-SET-03) is 3E. *(L1)*
- **AC-4** **Untyped and empty.** Bez hlavičky shows no `Properties` region and no subtitle; Jen systémové (only `id`, `type`, `title`, `created`, `modified`) shows only Created and Modified. *(L1)*
- **AC-5** **Collapsible (D-127).** The strip's header button `Properties` collapses and expands it; the state is per machine (UI state), applies to every note, survives a relaunch, and writes nothing to the vault. *(L5; L6 for relaunch)*
- **AC-6** **Read-only.** In the read view no attribute value is editable; on the editor route the attribute panel edits values (types.md FR-EDT-07). Checked through the read-view test switch `window.__TEGG_TEST__.readView` (D-215). *(L5)* *(changed by D-242: retired for the editor route)*

### NFR-PERF-05 Open a note (read-view part, slice 3B; AP-92)

- **AC-2** [MS3] **Read view opens in time.** On the reference machine and vault (performance.md), from ⏎ on a switcher result to the `note-ready` mark (the formatted view painted, links resolved and focus on the title), p95 of 20 runs is under **112 ms** (75% of 150 ms, D-59) for the vault's longest note (5,000 words) with 10 embeds and 50 links. The AC-1 row ("rendered and editable") is measured again with the editor at 3C. *(L6 benchmark, `qa/perf`)*
- **AC-3** **Link resolution is one batch.** Opening Odkazy sends exactly one link-resolution IPC call for all its links and attribute relations (no call per link), and `note_read` exactly once. *(L5)*

### NFR-REL-03 Invalid frontmatter in the read view (verifies data-safety NFR-REL-03 AC-1 [MS3])

- **AC-3** [MS3] **Opens in source view with a warning.** Opening each of Chyba uvozovky, Chyba odsazení, Chyba klíč, Chyba tabulátor and Neuzavřená shows the source view (FR-EDT-10) and, above it, a `alert`-role warning with the catalog message, the problem kind (`invalid YAML` or `frontmatter not closed`, D-97) and the line from `@tegg/doc` (`frontmatter.error.line` or `frontmatterError.line`): lines 3, 6, 5, 5 and 1 respectively (the values `@tegg/doc` reports today). The core's own message text isn't shown (NFR-OTH-02 AC-2). The app doesn't crash; the sidebar, palette and switcher keep working. *(L1 for message and line; L5 for the route)*
- **AC-4** [MS3] **Formatted view still available.** The toggle switches such a file to the formatted view, which renders the body (for Neuzavřená the whole file is body, D-97) with the warning still shown and no `Properties` region. *(L5)*
- **AC-5** [MS3] **Never rewritten.** Opening, toggling and closing these files leaves their bytes, mtime and inode unchanged (NFR-REL-03 AC-2). *(L6)*

### FR-SYN-03 External changes in the read view (slice 3B)

- **AC-10** [MS3] **Reload in place.** Given Cíl is open in the formatted view and scrolled to `Druhá kapitola`, when another program changes a paragraph above it, the view shows the new text within 2 s (NFR-PERF-08) and `Druhá kapitola` is still the first visible block (± one line); with the source view open, the source updates and the same line stays visible. No dialog, no write. (The editor cases AC-2…AC-4 stay 3C.) *(L4 for the event; L5 for the view)*
- **AC-11** [MS3] **Deleted or renamed while open.** When another program moves the open note to `.trash/` or deletes it, the centre pane shows a catalog message `This note was moved or deleted` with no content and no write; when it renames it, the view reloads from the new path (same `id`, FR-SYN-03 AC-5) and the breadcrumb shows the new file's folder (D-161). Links in other open views to the old name are re-resolved on the next `vault:changed`. *(L5; L4 for the rename identity)* *(breadcrumb part removed by D-315: the note page has no breadcrumb)*

### FR-SYN-06 No writes from the read view (slice 3B)

- **AC-6** [MS3] **Zero vault writes.** In the built app on a copy of the fixture, opening every fixture note, following every resolved link of Odkazy, activating every unresolved link, date link and tag, toggling the source view on each note, collapsing the attribute strip and folding each callout leaves every vault file's bytes, mtime and inode unchanged and creates no file or folder in the vault (D-119). *(L6; L5 counts zero write commands to the fake core during the same tour)*
