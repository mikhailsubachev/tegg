# Acceptance Criteria: Configurable columns on the type page (FR-TYP-09)

See [README](README.md) for conventions. Source: the owner's Preview v0.94 feedback (2026-10-30): any column can be removed or added (Title always stays), `Modified` doesn't have to be shown, many columns with horizontal scroll, and column widths changed by dragging and remembered. Builds on [types.md](types.md) FR-TYP-09 (type page, D-233, D-252, D-260), FR-TYP-11 (preview properties), FR-TYP-17 (hidden properties, D-316), AR-07 (versioned type files), and on [type-moves.md](type-moves.md) FR-TYP-04 AC-6…AC-10 (deleting a property, D-807).

**Status: approved, 2026-10-30.** The owner decided D-1240 and D-1241, then AP-1140…AP-1150 each as proposed (D-1242…D-1252, BRD v1.125).

**Owner decisions these criteria follow (2026-10-30, BRD v1.125):**

- **D-1240.** The chosen columns (which ones, in what order) are a new top-level key `columns:` in `.tegg/types/<key>.yml` (portable, a flow list of keys like `preview`), separate from `preview`. `preview` keeps its role and its 4-item limit for previews, embed cards and the graph (FR-TYP-11, FR-LNK-10, FR-EMB-02, FR-GRP-06), and from now on is edited only in Type settings. A type with no `columns` key shows its preview properties as columns, so existing vaults look the same until changed. Each change is one minimal atomic write, refused if the type file changed on disk (as FR-TYP-01 AC-7).
- **D-1241.** Column widths set by dragging are machine-local UI state in Application Support (per type key, like `typeSort` in `UiStateDto`). They are never written to the vault.

**Risk tiers (test-strategy §3).** Type-file writes (seeding, patching, conflict refusal, consistency on property delete) are **T1**: L4 bytes on APFS plus L5. Showing the right value in the right column, sorting and the fallback rule are **T2**. Layout, scrolling and resizing are **T3**.

**Test layers** as in [types.md](types.md): L1 Vitest (column model, width rules), L4 Rust (`tegg-schema` patch bytes; `tegg-core` writes, conflicts and the 4E job on a temporary APFS copy), L5 Playwright on WebKit with the fake core (records every call, including `ui_state_set`), L6 Appium on the built app (relaunch, a real pointer drag, vault checked by bytes, mtime and inode).

**Fixtures.** Synthetic only (D-50): `tests/fixtures/vaults/types/` with `new-empty/.tegg/` copied in, as in types.md. No fixture file changes. **Created at runtime by the tests** (added to the list in `tests/fixtures/vaults/README.md` when the tests are written):

## Reference table

### R130. Columns menu choices and defaults (D-1240; AP-1140, AP-1146)

The menu `Columns` (a `menu` of `menuitemcheckbox`es, as FR-TYP-09 AC-13) lists, in this fixed order (independent of the column order on the page):

| # | Item | Shown when | Key in `columns` | Checked when |
| --- | --- | --- | --- | --- |
| 1 | `Title` | always | — (never written) | always; `aria-disabled="true"`, description `Always shown` (AP-1140) |
| 2 | each attribute of the type, schema order, labelled with its Name (user content) | always (built-in attributes of system types included) | the attribute key | the key is in the effective columns |
| 3 | `Tags` | always | `tags` | as above |
| 4 | `Source` | always | `source` | as above |
| 5 | `Aliases` | always | `aliases` | as above |
| 6 | `Review` | the type's review workflow is `on` or `locked` (AP-1140) | `review` | as above |
| 7 | `Created` | always | `created` | as above |
| 8 | `Modified` | always (no longer fixed, D-1240) | `modified` | as above |
| — | separator, then `New property…` | not on Tag (D-693) | | |

`Description`, `id`, `type`, `title`, `icon`, `cover`, `previous`, `file`, `import-id`, `captured` are not choices (AP-1140).

**Effective columns** (the columns after Title, in order): the `columns` list when the key is present and readable (keys that are neither an attribute nor a universal choice of rows 3…8 are skipped, AC-25); else the shown preview columns: the `preview` keys that are attributes or rows 3…7 (`review` and `modified` skipped), in `preview` order, then `modified` (exactly today's columns, FR-TYP-09 AC-2).

**Widths** (D-1241; numbers from AP-1146): every column but Title starts at **160 px**. Title without a stored width fills the space the other columns leave, at least **240 px**; with a stored width it keeps that width and any spare space stays empty to the right of the last column. Minimum **80 px** (Title **160 px**), maximum **960 px**. Widths are CSS px of the `columnheader`, checked with `getBoundingClientRect().width` ± 1 px.

### FR-TYP-09 Type page: configurable columns

- **AC-18** **Columns come from `columns` (D-1240; T2).** Title is always the first column. (a) With the runtime `columns: [místo, datum]`, `type/schůzka`'s table has exactly the `columnheader`s `Title`, `Místo`, `Datum`, in that order: no `Modified` and no `Účastníci`, though `preview: [datum, účastníci]` is unchanged. (b) With no `columns` key (the fixture), the headers are `Title`, `Datum`, `Účastníci`, `Modified` (R130 fallback, identical to FR-TYP-09 AC-2 today); changing `preview` in Type settings to `[účastníci]` makes them `Title`, `Účastníci`, `Modified` within 1 s. (c) With `columns: []` the only header is `Title`. (d) A column that isn't in `preview` shows real values: with (a), Porada's `Místo` cell is empty (its `místo:` is empty) and, after the test sets `místo: Zasedačka` in Porada, shows `Zasedačka` within 2 s; the rows still come from one index query (`index_type_rows` returns a value for every effective column key, D-241), never from reading notes. Cells use the display of FR-TYP-09 AC-2; a `Review` cell shows `Unreviewed` / `Reviewed` (an other value with the invalid-value warning icon, FR-TYP-08 AC-11); a `Modified` or `Created` cell the D-160 date-time. *(L5; L1 for the column model; L4 for the query)*
- **AC-19** **Columns menu contents (D-1240; AP-1140).** On `type/schůzka` (review off) `Columns` opens the menu with the items `Title`, `Datum`, `Začátek`, `Účastníci`, `Projekt`, `Místo`, `Tags`, `Source`, `Aliases`, `Created`, `Modified`, separator, `New property…`; `Title`, `Datum`, `Účastníci` and `Modified` are checked (fallback), `Title` aria-disabled with `Always shown`, and activating it (click, Space, ⏎) writes nothing. On `type/nápad` (review on) the items are `Title`, `Hodnocení`, `Tags`, `Source`, `Aliases`, `Review`, `Created`, `Modified`; on `type/quick-note` (locked) `Review` is listed; on `type/task` the built-in `Status`, `Priority`, `Due date` (D-1254), `Completed`, `Recurrence` are listed in schema order. The menu stays open after each toggle; when it is taller than the window it scrolls, and ↑/↓ keep the highlighted item visible. ↑/↓, Space/⏎ and Esc work without the pointer; Esc returns the focus to `Columns`. *(L5)*
- **AC-20** **Toggling writes only `columns` (D-1240; AP-1141; T1).** On the fixture `schůzka.yml` (no `columns`, no `hidden`): (a) Checking `Místo` sends one `type_patch` and writes `.tegg/types/schůzka.yml` once, atomically, inserting exactly one line after line 11 (`preview: [datum, účastníci]`): `columns: [datum, účastníci, modified, místo]` (seeded from the effective columns, the new key appended at the end, AP-1142); every other byte, the `preview:` line included, is unchanged. Within 1 s the headers are `Title`, `Datum`, `Účastníci`, `Modified`, `Místo`. (b) Unchecking `Modified` then writes `columns: [datum, účastníci, místo]` (only that line changes). (c) Unchecking `Místo`, then checking it again, ends with `columns: [datum, účastníci, místo]`: the key is never removed once written, also when it equals the fallback, and unchecking every item writes `columns: []`. (d) Placement: on `osoba.yml`, unchecking `Firma` inserts `columns: [modified]` between `preview: [firma]` and `poznámka-pro-mě: ručně přidaný klíč`, and the comment `# Barvu vybrala Jana.`, the unknown key and the final newline stay byte-identical (AR-07 AC-5); on the runtime `schůzka.yml` with `hidden: [místo]` the line goes after the `hidden:` line; on `nápad.yml` checking `Review` writes `columns: [hodnocení, modified, review]` between `preview:` and `template:` (TOP order `… preview, hidden, columns, template, attributes`, AP-1141). (e) Seeding uses the shown columns only: with the runtime `preview: [datum, neznámý]`, checking `Místo` writes `columns: [datum, modified, místo]` and `preview: [datum, neznámý]` stays. (f) On the runtime `osoba.yml` without `version`, the first toggle also writes `version: 1` as the first key after the header comment (AR-07 AC-2) and nothing else. (g) Opening, sorting, filtering, scrolling and resizing a type page never writes `columns` (no lazy seeding; FR-SYN-06): no type-file write during those steps. (h) Five toggles within 1 s give five serialized writes, each based on the previous result, no `Conflict` and no alert, and the final file equals the one produced by the same toggles done slowly. No note file is written by any of these (bytes, mtime, inode). *(L5; L4 for the bytes)*
- **AC-21** **No limit on columns (D-1240).** On `type/projekt` (7 attributes, review off), checking every unchecked item in menu order gives 9 writes and ends with `columns: [stav, období, modified, rozpočet, aktivní, oblasti, web, poznámka, tags, source, aliases, created]` and 13 headers: `Title`, then those 12 in that order. No item is ever aria-disabled except `Title`; the texts `Up to 4 columns` and `Up to 4 columns. Choose it in Columns after unchecking another.` appear nowhere and are removed from the catalog. `preview: [stav, období]` is unchanged at the end. *(L5; L4 for the bytes)*
- **AC-22** **Modified is an ordinary column; the default sort (D-1240; AP-1144).** `Modified` can be unchecked, checked and moved like any other column (AC-20, AC-23). The default sort (no remembered sort for the type) is `Modified` descending when `Modified` is an effective column, else `Title` ascending (D-122 collation). On `type/schůzka` with the fallback columns the rows are Porada, Ve stránkách, Prázdná schůzka (modified 10-07, 10-05, 10-02); after unchecking `Modified` they are `2026-10-07 Porada`, `Prázdná schůzka`, `Schůzka ve stránkách` and the `Title` header has `aria-sort="ascending"`. A remembered sort (`typeSort`, FR-TYP-09 AC-3) on a column that is no longer shown is not used while it is hidden and is not deleted from the UI state: with the sort `Datum` ascending remembered, unchecking `Datum` sorts by the default, and checking `Datum` again restores `Datum` ascending. Sorting rules of FR-TYP-09 AC-3 apply to every column; `Review` sorts by its label (collation), empty last. Exactly one header has an `aria-sort` other than `none`. *(L5; L1 for the rule)*
- **AC-23** **Reordering columns (AP-1142).** Dragging the header `Místo` (pointer down on the header text, not on the resize handle, moved more than 4 px) and dropping it before `Datum` on the runtime `columns: [datum, účastníci, modified, místo]` writes `columns: [místo, datum, účastníci, modified]`, one write, only that line changes; a press without moving more than 4 px is a click and sorts (FR-TYP-09 AC-3). With a header focused, ⌥← / ⌥→ move it one place (one write each) and the focus stays on the moved header. `Title` can't be dragged or moved, nothing can be dropped before it, and ⌥← on the first column after Title or ⌥→ on the last one writes nothing. On a type without `columns`, the first move seeds the key as AC-20. *(L5; L4 for the bytes)*
- **AC-24** **New property from the menu adds a column, not a preview (D-1240).** On `type/schůzka`, `New property…` opens the Add property flow of FR-TYP-03 AC-1; `Add` with Name `Telefon do práce` sends one `type_patch` that appends the property item at the end of `attributes:` **and** writes `columns: [datum, účastníci, modified, telefon-do-práce]` (seeded, appended) in the same single write of `schůzka.yml`; `preview` is unchanged whatever its length; no limit message is shown; the new column is the last header within 1 s. Cancel writes nothing. `Add property` in Type settings writes the item only and doesn't touch `columns` (AP-1141). *(L5; L4 for the bytes)*
- **AC-25** **Hand-written and malformed `columns` (AP-1143; T1, T2).** (a) With the runtime `columns: [datum, neznámý, datum, title, místo]`, the headers are `Title`, `Datum`, `Místo`: the unknown key `neznámý` is skipped, a repeated key is shown once (first place), `title` is skipped; the menu shows the warning `Not a property of Schůzka, kept in the file: neznámý` (user content in the key list); checking `Created` writes `columns: [datum, neznámý, datum, title, místo, created]` (every hand-written entry kept in place), and unchecking `Datum` removes every `datum` entry: `columns: [neznámý, title, místo, created]`. (b) The NFD runtime entry `místo` matches `Místo` (checked, shown); the next write writes every entry in NFC (FR-FMT-12). (c) A hand-written block list is read like a flow list; the next write replaces its lines with one flow-list line, the other lines unchanged (as `preview`, §14.1.4). (d) `columns: datum` (scalar) and `columns: { a: b }` (mapping) don't make the type file invalid (AR-07 AC-4 is unchanged): the table shows the fallback columns, `Columns` is aria-disabled with the description `The columns setting in .tegg/types/schůzka.yml can't be read. Fix it in the file to change columns.`, no type write is sent, and the file keeps its bytes. *(L5; L1 for the model; L4 for the bytes)*
- **AC-26** **Kept consistent with schema changes (D-1240, D-807; T1).** (a) Deleting a property removes its key from `columns` in the same type-file change that removes the item and its `preview` and `hidden` keys: in the 4E job of type-moves.md FR-TYP-04 AC-7 (Kniha `poznámka`, with a runtime `columns: [autor, poznámka, modified]`) `kniha.yml` ends with `columns: [autor, modified]`, and its Undo (AC-8) restores `kniha.yml`'s exact bytes, the `columns` line included; on the no-value path (`isbn`, AC-6) the single write of `kniha.yml` does the same. Every occurrence of the key is removed (also a repeated or NFD-spelled one). (b) Renaming a property's Name changes no `columns` line and the header shows the new Name within 1 s. (c) Widening a property's type (D-808) keeps its column; the cells follow the new type's display. (d) Changing the type's Name, Plural, icon, colour, folder or review workflow never writes `columns`; turning the review workflow off while `review` is a column keeps the key in the file and hides the column and its menu item until it is turned on again (AP-1140). *(L4; L5)*
- **AC-27** **Failures and where Columns is not offered (D-1240; T1).** (a) **Conflict:** when `schůzka.yml` changed on disk since it was read (L5: fake core changes it silently; L4: other bytes on disk), a toggle, a move or `New property…` is refused with `Conflict`, nothing is written, the alert of FR-TYP-01 AC-7 names `Columns`, and the table and the menu show the disk state. (b) **Missing system file:** in a vault without `.tegg/types/task.yml`, checking `Completed` on `type/task` creates the file equal to `new-empty/.tegg/types/task.yml` plus one line `columns: [status, priority, due, modified, completed]` after its `preview:` line (D-90, FR-TYP-06 AC-4); if the file appears meanwhile, `Conflict` as (a). (c) **Newer version:** `budoucí.yml` with the runtime `columns: [hodnota, created]` shows the headers `Title`, `Hodnota`, `Created` (read, D-1240 applies to reading); `Columns` is aria-disabled with AR-07 AC-3's reason and no type write is sent. (d) **Invalid file:** `rozbitý` shows `Title` and `Modified`; `Columns` is aria-disabled with AR-07 AC-4's reason. (e) **Undefined type** (`type/recept`, shell fixture): no `Columns` (FR-TYP-09 AC-10), headers `Title` and `Modified`; resizing (AC-30) works and is stored under the key `recept` in the UI state (AP-1146). In (c)…(e) every file keeps its bytes. *(L4; L5)*
- **AC-28** **Live update (D-1240).** With `type/schůzka` open (fallback columns, the sort `Datum` ascending, `Datum` resized to 240 px), another program writes `columns: [místo, datum]` into `schůzka.yml`: within 2 s (NFR-PERF-08) the headers are `Title`, `Místo`, `Datum`, the sort and the 240 px width are kept, an open `Columns` menu shows the new checks, and nothing is written. When the external change removes the sorted column, the table sorts by the default of AC-22. Deleting the `columns` line from outside returns the table to the fallback columns. *(L5; L4 for the watcher)*
- **AC-29** **Horizontal scroll with a sticky Title (AP-1145).** On `type/projekt` with the 13 columns of AC-21, in a 1280 × 800 window with the right panel closed: the table's scroll container has `scrollWidth > clientWidth` and scrolls horizontally (trackpad, ⇧ + wheel; Playwright `mouse.wheel` with `deltaX`), the header row and the body scroll together, and the page itself has no horizontal scroll bar. Scrolled to the far right, the `Title` header and every visible Title cell keep their left edge at the container's left edge (± 1 px), have an opaque background (computed `background-color` alpha 1) in light and dark, and the other cells pass under them, never over them. Tab from `Title` through the headers scrolls each focused header fully into view to the right of the Title column; ↑/↓ on rows don't change `scrollLeft`. With the 4 fallback columns at the same size there is no horizontal scroll and Title fills the rest (R130). A row click still previews and ⏎ / a double-click opens (previews.md R104 row 9) at any scroll position. On the runtime `široký` type with all 30 columns checked, the same holds. *(L5)*
- **AC-30** **Resize by pointer (D-1241; AP-1146).** Every header, `Title` included, has a resize handle on its right edge (`separator`, `aria-orientation="vertical"`, accessible name `Resize <column>`, cursor `col-resize`, at least 8 px wide hit area). On `type/schůzka`: dragging `Resize Datum` 100 px right makes `Datum` 260 px wide; the columns to its right move, none changes width. Dragging 500 px left stops at 80 px; `Resize Title` dragged to 100 px stops at 160 px; any drag stops at 960 px. Pressing on the handle, dragging and releasing never sorts, never previews a row and never starts a reorder (AC-23). Esc during a drag restores the width from before the drag. A double-click on a handle resets that column to its default (R130; Title back to filling) and doesn't sort. The width shown is the width of the header and of every cell of the column (rows virtualized or not). Long cell content is cut with an ellipsis, never wraps into a taller row, and the full text is the cell's `title` tooltip. *(L5; L1 for the clamping; L6 once for a real drag)*
- **AC-31** **Resize by keyboard and reset (FR-UX-03; AP-1147).** Tab order in the header row is: header, its resize handle, next header, …. With `Resize Datum` focused: `aria-valuenow` is the width in px (160), `aria-valuemin` 80, `aria-valuemax` 960; → / ← change it by 10 px, ⇧→ / ⇧← by 50 px, Home / End set the minimum / maximum, ⌫ or Delete reset it to the default; each change updates `aria-valuenow` and the column at once. The `Columns` menu ends with `Reset column widths` (after `New property…`, separated), and the palette has `Choose columns…` (opens the `Columns` menu) and `Reset column widths` on `type/<key>` routes of defined types (only `Reset column widths` on undefined types); `Reset column widths` returns every column of this type to R130's defaults and leaves other types' widths alone. None of these writes to the vault. *(L5)*
- **AC-32** **Widths are machine-local, per type, and survive relaunch (D-1241; T1 for the vault part).** Widths are stored in the UI state (Application Support) under the type key and the column key (`typeColumnWidths`, contract to add, `UiStateDto.version` stays 1 as §14.10 item 12). After `Datum` is set to 260 px on `type/schůzka` (pointer, L6) and `Hodnocení` to 200 px on `type/nápad` (keyboard): the UI state is written at most once per drag (on release) and within 1 s of the last keyboard change; `type/projekt` shows R130 defaults; after quitting and relaunching, `type/schůzka` shows `Datum` at 260 px and `type/nápad` `Hodnocení` at 200 px. A width is kept when its column is unchecked and comes back with it (AP-1146); a column key with no column (e.g. after a property delete) is ignored. No vault file is created, changed or moved by any resize or reset (bytes, mtime and inode of every vault file unchanged; no `vault:changed`; no new file under `.tegg/`). A vault opened on a second Application Support (second "machine") shows R130 defaults while the `columns` choice of AC-20 is the same on both. *(L5; L6 for relaunch and the second Application Support)*
- **AC-33** [MS8] **Many columns stay fast (NFR-PERF-07; AP-1148).** On the reference machine and vault, with a runtime `columns: [tags, source, aliases, review, created, modified]` on `quick-note.yml`, `type/quick-note` with 1,000 objects paints its first rows in under 225 ms, p95 of 20 runs (the AC-12 target); at most 100 row elements are in the DOM while scrolling vertically and every rendered row has one cell per column (7). On the runtime `široký` type with 30 columns and 300 objects (L5): at most 100 rows in the DOM, each with 31 cells; scrolling to the last row and back shows `Řádek 300` and `Řádek 001`. Columns are not virtualized (AP-1148). *(L6 benchmark; L5 for the DOM counts)*
- **AC-34** **Themes, strings, palette (FR-UX-05, NFR-OTH-02, FR-UX-03).** FR-UX-05 AC-4 and AC-5 pass, light and dark, on `type/projekt` with 13 columns scrolled half way, the `Columns` menu open (warning of AC-25 shown) and a resize handle focused; the resize handle and its focus ring have at least 3:1 contrast against the header in both themes. Every new label, description, warning and command title comes from the catalog: `Always shown`, `Resize {column}`, `Reset column widths`, `Choose columns…`, `Not a property of {type}, kept in the file: {keys}`, `The columns setting in {file} can't be read. Fix it in the file to change columns.`, `Review` (menu item); attribute Names and keys are user content (`data-user-content`). `Choose columns…` and `Reset column widths` are listed in the palette on type routes (AC-31). *(L1; L5)*

### FR-TYP-11 Preview properties

- **AC-4** **Preview and columns are separate (D-1240).** (a) Every Columns action (AC-20…AC-25, AC-27) leaves the `preview:` line byte-identical. (b) On a type with a `columns` key, adding, removing or reordering preview chips in Type settings writes only the `preview:` line (FR-TYP-11 AC-1, still up to 4) and the type page's columns don't change. (c) On a type without `columns`, the same change changes the type page's columns (fallback, AC-18 (b)) and writes nothing else. (d) The preview strip (previews.md), embed cards (FR-EMB-02) and graph node details (FR-GRP-06) follow `preview`, never `columns`: with the runtime `columns: [místo, datum]`, Porada's preview strip shows `Datum` and `Účastníci` only. *(L5; L4 for the bytes)*

### AR-07 Versioned type definitions

- **AC-8** **`columns` is an optional key of version 1 (AP-1149).** `tegg-schema` reads `columns` as an optional flow or block list of strings; `CURRENT_VERSION` stays 1 and a file with `columns` and `version: 1` is `Ok`, never `Newer`. New type files (FR-TYP-01 AC-2, `tests/fixtures/types/expected/čajovna.yml`), starter files (R11) and built-in system files (D-90) are written without `columns` and stay byte-identical to their fixtures. Every type op other than the columns op (and `RemoveAttribute`, AC-26) leaves the `columns` lines byte-identical, including a hand-written block list and a malformed value (AC-25 (d)). AR-07 AC-6 (round trip) passes for each runtime variant above that has a readable `columns` key. *(L4)*
