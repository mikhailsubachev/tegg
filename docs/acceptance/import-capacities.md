**Overall acceptance (§11.1):** every object, attachment and link in the selected space is either imported or listed in the import report. Nothing disappears silently.

**Slices.** Each criterion ends with its slice.

**Scope.** FR-IMP-03, -05, -07…11, -14…17, -19…22, -24, FR-TYP-15 (import part), FR-HIS-04 (backup before an import into a non-empty vault, D-57), FR-UX-07 (progress and cancel, D-110), and this slice's checks of FR-SYN-02, FR-SYN-06, FR-FMT-07, -08, -11, -12, FR-LNK-14, FR-ATT-07, FR-TAG-03, FR-DLY-08, FR-UX-03, FR-UX-05, FR-UX-08, NFR-OTH-02, AR-03 and NFR-SEC-01. **Out of scope, later slices:** Obsidian (FR-IMP-01, FR-STO-10; the board's section B), Notion (FR-IMP-02, -12, -13), Anytype (FR-IMP-04). **Risk tiers** (test-strategy §3). The importer creates hundreds of files in one run and may write into the owner's own vault. **T1, data loss:** an existing vault file changed, replaced or removed by an import; a partly written vault left looking complete; a source file modified; an object, attachment or link dropped with no report row. These criteria are marked **(T1)** and check bytes, mtime and inode. **T2, silently wrong data:** a date shifted by a time zone; a link bound to another object than the source meant (duplicate titles, case, NFC/NFD, an existing object of the same name); a value merged or converted wrongly; preview counts that differ from what was written. These are marked **(T2)**.

**Shared definitions.** **Source** is the chosen zip or folder. **Target** is the vault written to: a **new vault** or an **existing vault**. **Plan** is the engine's full answer before any write: every object with its target path, every attachment, every link with one outcome, every report row. **Default mapping** is the mapping the engine proposes with no user choice (R148). **Untouched** means bytes, mtime and inode unchanged. **Written vault** is the target after a finished import.

## Reference tables

### R147. What the engine counts (FR-IMP-05, §11.1, D-79; S5 accounting)

| Class | Rule (D-79) | Outcomes; each item has exactly one |
| --- | --- | --- |
| Object | every `.md` in the selected space that is not a dotfile | **imported** (written as one object file) · **skipped by the mapping** (`Don’t import`, AP-1320) · **unreadable** (frontmatter that isn't valid YAML, no `type:`) |
| Attachment | every other file in the selected space except `.csv` and dotfiles | **imported** (in `_attachments/`, with an Image or PDF object) · **unreadable** |
| Other file | `.csv` (tag collection or other), dotfiles (`.DS_Store`, hidden `.md`) | **reported** only |
| Link | every wikilink, Markdown link and image outside code, in bodies and frontmatter values, found by a Markdown parser (F12) | **resolved** · **date mention** · **attachment** · **external** (a URL with a scheme; kept, not a vault link) · reported: **unresolved**, **other space**, **ambiguous** (D-76), **case mismatch** (D-81), **select value** (FR-IMP-21), **missing file**, **in a skipped note**, **target not imported** (AP-1320) |

The **accounting check** recomputes the three totals from the raw entries with its own rules (space membership by path, classes by extension, a separate link counter), sharing no code with the planner or the scanner, and requires `imported + reported = total` for objects, attachments and links, with every reported item present in a report list. It runs on the plan and again on the written vault.

A **mapping** is data: per source type, the target (an existing type, a new type with its name, or `skip`); per source attribute, the target (an existing attribute, a new attribute with its name and kind, or `drop`) and its options (value merges with the spelling kept, status meanings, `split`); and the answers of step 4c (confirmed case-only links, link-select attributes). The engine accepts a partial mapping and fills the rest with the defaults.

### R149. What the write phase produces (FR-IMP-03; AP-1316, AP-1322, AP-1331)

- **Object file:** `<type folder>/<file name>.md`. Frontmatter keys in the order `id, type, title, description, aliases, <attributes in source order>, tags, import-id, created, modified` (AP-1331); `type` is the type key (D-96); absent and `null` values are omitted; values are quoted by the same rule as Tegg's own writes (D-230). LF line endings, NFC, a final newline.
- **Body:** the source body with only these changes: link spans and media spans rewritten (FR-IMP-10, -14), invisible characters removed (FR-IMP-17), CRLF → LF. Every other byte, including code spans, code blocks, checklists and Capacities' own scaffolding, stays.
- **Attachments:** copied byte for byte into `_attachments/`, never moved out of the source.
- **Type files:** one new `.tegg/types/<key>.yml` per new type; an existing type file changes only by attributes appended to it (AP-1322).
- **Report:** one Page (R150), written last.
- **Order:** type files, attachments, objects in source-path order, the report. Each file is written to a temp file in its folder and renamed (FR-SYN-02). An existing file is never replaced: every create is exclusive.
- **New vault:** written under a temporary name next to its final place and renamed to the final name after the report is written, so a vault folder with the final name is always complete (AP-1316).
- **A vault or source that changes meanwhile (D-1547…D-1549):** planned paths are checked again before the first write, and no create or rename ever replaces a file that arrived (FR-IMP-03 AC-12); a type file is extended only if it is still the file the plan read (AC-13); the temporary folder carries a marker, and the final rename replaces nothing (AC-14); a source that changes during the write phase fails the run (AC-15). How "create without replacing" is done on APFS is for the contract.

### R150. The report Page (FR-IMP-19; AP-1311)

File `Pages/Import report <YYYY-MM-DD> <space>.md`, title the same without `.md`, type Page, no `import-id`. The date is the import day in the machine's zone. A taken name gets ` (2)`. Sections, in this order, each omitted when empty, each row linking to the affected object with a wikilink:

| Section | Rows |
| --- | --- |
| Summary | source, space, date; objects, attachments and links: imported, reported, total |
| Types | per source type: count, target type, `new` when created |
| Unresolved links | the linking object, the link text as written in the source, the reason (`not in the export`, `in another space: <space>`, `target not imported`, `missing file`, `in a skipped note`) |
| Ambiguous links | the linking object, the title, the object chosen (D-76) |
| Links that differ only in case | the linking object, the link text, the candidate, `confirmed` or `left unresolved` (D-81) |
| Simplified links | the linking object, the link text as written in the source, the plain text kept as the alias (formatting or an image in a link's text, D-1533; FR-IMP-10 AC-9, AC-12) |
| Attributes | renamed (`source` → `source-text`), dropped (with the count of values), new, and link values turned into select values (FR-IMP-21) |
| Merged values | per attribute: the variants and the spelling kept |
| Dates | values that couldn't be read as dates (AP-1315) |
| Files | dropped references to missing files; media no note referenced (D-77); renamed generic names; file names changed (reserved stems, cut to 200 bytes, ` (2)` suffixes) |
| Query stubs | each stub |
| Skipped | notes that couldn't be read, with the reason; ignored files; types not imported by the mapping, with counts |
| Clean-up | counts per character removed (U+200B, U+FEFF, U+200C, U+200D), files with CRLF |
| Not in the export | `Query definitions`, `Tag colours and collections`, `Comments` |

The report's own text (section names, reasons) comes from the string catalog in the app's language at import time; after that it is file content.
