# Acceptance Criteria: Daily notes (MS4 slice 4B)

See [README](README.md) for conventions. Milestone MS4 (BRD §11.2), slice **4B "Daily notes"** (D-267; plan `docs/plans/ms4-implementation-plan.md` §3). Today (⌘D) stops being a placeholder: every calendar date has exactly one Daily Note (D-318), virtual until the first keystroke (FR-DLY-02), with previous/next day, a calendar with marked days, live context sections (D-271), `review: unreviewed` on the first write (D-272), the daily template (D-270), date rows in the `@` list (D-258) and date links that open the virtual note (D-142 replaced). The title is the date and fixed (D-320); duplicates for one date are shown, never merged (D-319). 4B writes only the Daily Notes the user types into and the notes the user edits (plan §5). Exit goal: the owner uses daily notes every day and links dates from any note.

**Status: accepted, 2026-10-15.** AP-243…AP-260 (end of this file) were accepted as recommended: D-321…D-338 (BRD v1.49).

**Follow-up (slice 4B preview feedback, 2026-10-16; `docs/feedback/ms4-4b.md`).** D-367: a Daily Note opened by a create path (FR-DLY-01 AC-5) gets the caret at the start of its first body block (editor.md FR-EDT-01 AC-13). D-369: the type chip of a Daily Note is a link to `type/daily-note`, no longer a disabled button (FR-DLY-01 AC-9 annotated; types.md FR-TYP-07 AC-11). D-368 changes the backlinks panel (backlinks.md), which a Daily Note shows as any note.

**Scope.** FR-DLY-01 (one per day, Today, D-318, D-319), FR-DLY-02 (virtual note, first write), FR-DLY-03 (previous/next, calendar), FR-DLY-04 (context sections, D-271), FR-DLY-05 (review status, D-272), FR-DLY-06 (template, D-270), FR-DLY-08 (date mentions and date links, D-142, D-162, D-258), FR-FMT-09 (the daily file name at the first write) and the 4B part of FR-SYN-06. **Out of scope:** the Inbox listing (FR-INB-01, MS5, D-272); tasks due/overdue (FR-TSK, MS5: a placeholder here, D-271); weekly/monthly notes (FR-DLY-07, backlog); time-stamped entries (FR-DLY-09, v1.0); templates beyond D-270 (FR-TPL, v1.0); merging duplicate Daily Notes (4C, AP-218); renames (4C; a Daily Note is never renamed, D-320); the setting UI for `daily-format` (the value is read from `vault.yml`).

### FR-DLY-01 One Daily Note per day, Today

- **AC-1** **⌘D and Today open today's date (TZ).** With the test clock, ⌘D (focus anywhere: body, title, sidebar, palette closed), the sidebar entry `Today` and the palette `Go to Today` each open `daily/2026-10-14`; the title field shows `2026-10-14` and the subtitle the R19 long date for the region (`cs`, `en`). In both zones it is 14 Oct (12:00 Prague, 03:00 Los Angeles). Each open is recorded with `nav_opened` (D-138); Back returns to the previous route. None of them sends a write command. *(L5; L6 once for ⌘D on the built app)*
- **AC-2** **Midnight is local (TZ, T2).** With the clock at local `2026-10-14T23:59:59`, ⌘D opens `daily/2026-10-14`; at local `2026-10-15T00:00:00` it opens `daily/2026-10-15`. With the instant `2026-10-14T22:30:00Z`, ⌘D opens `daily/2026-10-15` in Europe/Prague (00:30) and `daily/2026-10-14` in America/Los_Angeles (15:30). Changing `TZ` while the app runs changes the date of the next ⌘D without a restart. *(L1 for `localDate`, D-340; L5)*
- **AC-3** **Midnight while a note is open (D-327).** On `daily/2026-10-14` at 23:59:58, after the clock passes midnight the open note stays 14 Oct (no automatic switch), typing still goes into 14 Oct (its first write has `date: 2026-10-14`), the sidebar `Today` description becomes the 15 Oct long date within 60 s, and the next ⌘D opens 15 Oct. *(L5)*
- **AC-4** **An existing note opens, never a second one (D-318).** On 7 Oct (existing), ⌘D with the clock at `2026-10-07T12:00+02:00` opens `daily/2026-10-07` showing `Daily/2026-10-07.md`'s body. Archiv opens for `daily/2026-10-10` wherever it lives and whatever its file name (FR-FMT-09 AC-2). The core's `daily_note(date)` returns exactly: 1 Oct, 7 Oct, Pátek, Archiv and 12 Oct (2) for 1, 7, 9, 10, 12 Oct; `None` for 5 Oct (trashed, D-102), 14 Oct and 16 Oct (Kolize has no `date`); a file in `_templates/` with a `date` is never returned. *(L4; L5)*
- **AC-5** **Create commands open today's note (D-318).** With the clock on 14 Oct: the palette `New object` → `Daily Note`, the `New` button on the Daily Notes type page (types.md), and any other create entry point with the type Daily Note, each open `daily/2026-10-14` (virtual) and write nothing (D-367: with the caret at the start of the first body block, editor.md FR-EDT-01 AC-13). With the clock on 7 Oct, they open the existing 7 Oct note. The core creation path (D-232) refuses `note_create` with type `daily-note` (error `UseDailyNote`), so no caller can make a second file; the fake core enforces the same. *(L4 for the refusal; L5)*
- **AC-6** **Two notes for one date: the newest opens (D-319, TZ).** `daily/2026-10-12`, the calendar's 12 Oct and Zmínky's `[[2026-10-12]]` open `Daily/2026-10-12 (2).md` (latest `created`). Ordering is by instant, not text: with 12 Oct's `created` changed to `2026-10-12T21:30:00+03:00` (= 18:30Z, older than (2)'s 19:00Z) (2) still opens; with it changed to `2026-10-12T22:00:00+02:00` 12 Oct opens within 2 s. With equal `created`, the later `modified` wins; with both equal, the path that sorts first by byte order of the NFC path (D-335). A note without `created` is older than any note with one (D-335). Same result in both zones. *(L4; L5)*
- **AC-7** **The duplicate notice (D-319).** On `daily/2026-10-12` the R19 notice `1 other note has this date:` lists the link `Daily/2026-10-12.md`, which opens it as `note/Daily/2026-10-12.md` (that note shows the same notice naming `Daily/2026-10-12 (2).md`), and the link `Duplicate titles` opens the route `duplicate-titles`. The notice has plural forms (D-133). Without duplicates there is no notice. Opening, reading and following the notice write nothing; nothing is merged, renamed or deleted (both files keep bytes, mtime and inode). *(L5; L6 once for bytes)*
- **AC-8** **Duplicate titles listing (D-319, FR-LNK-14 AC-8).** The `duplicate-titles` page has a group `2026-10-12` with both notes (type Daily Note, each with its `created`). Deleting `Daily/2026-10-12 (2).md` externally removes the group and the notice within 2 s, and 12 Oct opens `Daily/2026-10-12.md`. A third Daily Note created externally with `date: 2026-10-12` and the newest `created` becomes the one that opens within 2 s, and the notice says `2 other notes have this date:`. Pátek (title `Pátek`, date 9 Oct) is not a duplicate of anything; its group key is its date (D-334). *(L4 for the grouping; L5)*
- **AC-9** **Fixed type (D-224, D-320).** On any Daily Note the type chip is aria-disabled with `The type of Daily Note objects can't be changed`; the type menu of any other note doesn't offer Daily Note; `Change type` from the palette isn't run. *(L5)* *(chip part superseded by D-369: the chip is the link `Type: Daily Note` opening `type/daily-note`, and the disabled reason moves to `Change type…` in the palette and the `More` menu, types.md FR-TYP-07 AC-11; the rest stands)*

### FR-DLY-02 Virtual until the first keystroke

- **AC-1** **Opening writes nothing (FR-SYN-06, T1).** Opening `daily/2026-10-14`, `daily/2026-10-20` and `daily/2026-10-16` by ⌘D, the calendar, previous/next and Zmínky's links; placing the caret; scrolling; opening the Context panel; and then navigating away (Back, ⌘D, sidebar, palette, closing the window, quitting the app, switching vault): no write command is sent, and the vault's file list, every file's bytes, mtime and inode, and `Daily/` are unchanged (no `Daily/2026-10-14.md`, no temp file). The virtual marker `Not saved yet…` is shown. Reopening shows the same virtual note again. *(L5 for the commands; L6 for the vault)*
- **AC-2** **The first keystroke creates exactly one file (T1).** On virtual `daily/2026-10-14` typing `Dnes` and waiting for `Saved` writes exactly one file, `Daily/2026-10-14.md`, through the one creation path (D-232) as create-exclusive temp + rename in `Daily/` (FR-SYN-02); no other vault file changes. Its frontmatter, in this order (D-324): `id` (new ULID), `type: daily-note`, `title: "2026-10-14"`, `date: 2026-10-14`, the template's other keys (`tags: [deník]`), `review: unreviewed`, `created` and `modified` (the test clock with the zone's offset: `2026-10-14T12:00:00+02:00` in Prague, `2026-10-14T03:00:00-07:00` in Los Angeles); then the expanded template body (FR-DLY-06 AC-1) with the typed text where the caret was (D-322). `date` is a bare `YYYY-MM-DD` (FR-FMT-11) and `title` is quoted so YAML reads it as a string. The virtual marker disappears; further typing autosaves into the same file (editor FR-EDT-09). *(L4 for the bytes; L5; L6 once on the real core)*
- **AC-3** **What counts as a keystroke (D-323).** Any edit that changes the document counts: typing, paste, drop, Enter, a slash-menu insert, a checklist toggle. Moving the caret, selecting, copying, ⌘Z with nothing to undo, opening menus and the `@` or `[[` list without choosing don't. If every change is undone before the autosave fires, nothing is written. *(L5)*
- **AC-4** **Leaving right after typing.** Typing one character and pressing ⌘D or Back within 50 ms flushes the pending save (editor FR-EDT-09 rule) and writes the AC-2 file once; quitting the app (⌘Q) within 50 ms of the keystroke does the same before exit. *(L5; L6 for ⌘Q)*
- **AC-5** **Crash during the first write (T1).** Killing the core process (SIGKILL) at each of the injected points before the rename, between rename and index update, and after it, leaves either no `Daily/2026-10-14.md` or a complete one with the AC-2 frontmatter; never a partial file, never an orphaned temp file after the next start (data-safety FR-SYN-02 cleanup). After restart `daily/2026-10-14` shows the file or the virtual note accordingly. *(L4 with fault injection)*
- **AC-6** **Name collision (FR-FMT-08).** On virtual `daily/2026-10-16` (Kolize is `Daily/2026-10-16.md`, a page), the first keystroke writes `Daily/2026-10-16 (2).md` with `date: 2026-10-16` and `title: "2026-10-16"`; Kolize keeps its bytes, mtime and inode. Afterwards `[[2026-10-16]]` resolves to the new file (date first, D-162). *(L4; L5)*
- **AC-7** **Another note for the date appears meanwhile (T1, D-326).** With virtual `daily/2026-10-14` open and nothing typed, another program creating a Daily Note with `date: 2026-10-14` (any path) makes the view show that file within 2 s, with no write by Tegg. If the user has already typed and the file appears between the keystroke and the first write, the core re-checks `daily_note(date)` at creation: it writes the user's note as a new file (`Daily/2026-10-14 (2).md` if the name is taken), never into or over the other file, and the D-319 notice appears; the other file keeps its bytes. *(L4; L5)*
- **AC-8** **Write failure.** If the first write fails (`Io`, read-only vault), the typed text stays in the editor, the save status shows the catalog error, the note stays virtual, nothing partial is left, and the next keystroke retries. *(L5; L4 for no partial file)*
- **AC-9** **Emptying never deletes (D-338).** Deleting all text of a written Daily Note saves an empty body; the file stays (with its frontmatter) and is still marked in the calendar. *(L5)*
- **AC-10** **Property test.** For random sequences of {open date d, type, undo, navigate away, external create/delete of a Daily Note for d, quit} on dates around month, year and DST boundaries: after each step the vault holds a Daily Note file for d only if a keystroke on d changed the document or an external program created one, and at most one file is written by Tegg per date (FR-SYN-06). *(L2, Rust model against the core)*

### FR-DLY-03 Previous/next day and calendar

- **AC-1** **Previous and next are calendar days (TZ).** From `daily/2026-10-14`, `Next day` (button, ⌥⌘→, palette) opens `daily/2026-10-15` (virtual) and `Previous day` opens `daily/2026-10-13` (virtual), regardless of which days have notes (D-329). Boundaries: next of 2026-10-24 → 2026-10-25 → 2026-10-26 (Prague DST end, no day skipped or repeated); next of 2026-10-31 → 2026-11-01 → 2026-11-02 (Los Angeles DST end); previous of 2026-03-01 → 2026-02-28; next of 2026-12-31 → 2027-01-01; next of 2028-02-28 → 2028-02-29. Each step is one `nav_opened` and writes nothing. *(L1 for date arithmetic; L5)*
- **AC-2** **Shortcuts don't steal editing keys.** ⌥⌘← / ⌥⌘→ run only on `daily/…` routes; on other routes and inside the `@` / `[[` list they do what they did before 4B. FR-UX-03 AC-7 (no shortcut conflicts) passes with R17. *(L5)*
- **AC-3** **The calendar marks days with notes.** `Pick date` (or `Go to date…`) opens R18 on October 2026 with the open date selected and today `aria-current="date"`. Exactly 1, 7, 9, 10 and 12 have `data-has-note="true"`; not 5 (trashed), 16 (Kolize has no `date`), 14 (virtual) or any date only linked from Zmínky (20). The marks come from the core (`daily_dates(month)`), which returns the same set after deleting and rebuilding the index (AR-01). *(L4; L5)*
- **AC-4** **Marks are live.** Typing on virtual 14 Oct marks 14 within 1 s of `Saved`; another program creating `Daily/2026-10-20.md` with `date: 2026-10-20` marks 20 within 2 s; deleting 1 Oct externally or moving it to `.trash/` unmarks 1 within 2 s; changing Archiv's `date:` to `2026-10-11` moves its mark from 10 to 11 within 2 s. The calendar can stay open meanwhile. *(L4; L5)*
- **AC-5** **Choosing a day.** Clicking 20 or moving to it with the arrow keys and pressing ⏎ opens `daily/2026-10-20` (virtual) and closes the calendar; Esc closes it and returns the focus to `Pick date`. Arrow keys move by day and week, PageUp/PageDown by month, Home/End to the week's start/end; `Previous month` / `Next month` change the month and its marks (September 2026 has none; November 2026 none). Opening, browsing and closing write nothing. *(L5)*
- **AC-6** **Locale.** With region `cs` the week starts on Monday and the header is `říjen 2026`; with `en-US` on Sunday and `October 2026` (D-329). Day names and dates come from the region's formats (D-133), not from code. *(L5, D-354)*

### FR-DLY-04 Context sections

- **AC-1** **Sections shown, in order (D-271, D-328).** On `daily/2026-10-14`, virtual or written, after the body: `Quick Notes`, `Tasks due`, `Created`, `Modified` (R19). Each row is the object's type icon and title (a link that opens it, D-255); rows are sorted by the attribute's instant, newest first. `Tasks due` lists tasks since 5A-1 (tasks.md FR-DLY-04 AC-8…AC-14, D-489). *(L5)*
- **AC-2** **Contents in Europe/Prague.** For 14 Oct: Quick Notes = Nápad z rána; Created = Nová stránka dne; Modified = Upravená stránka. Nápad z rána is not repeated in Created and an object in Created is not repeated in Modified (D-328). Bez data is in no section (no `created`/`modified`, D-271); templates, `.trash/` and the Daily Note itself are never listed; other Daily Notes created or modified that day are listed in Created / Modified (D-328). For 15 Oct: Quick Notes = Pozdní nápad. For 7 Oct the note itself (created that day) is excluded, so every section shows `Nothing yet` except the placeholder. *(L4 for the query; L5)*
- **AC-3** **Contents in America/Los_Angeles (TZ, T2).** For 14 Oct: Quick Notes = Pozdní nápad (15:30 local); Created = Nová stránka dne (exactly 00:00:00 local: the start is inclusive); Modified = Upravená stránka. For 13 Oct: Quick Notes = Nápad z rána (22:30 local). The day of an instant is taken in the current zone, not from the offset written in the file (D-328). A `created` without an offset is read as local time (D-328). *(L4; L5)*
- **AC-4** **Live, never saved (T1).** With 14 Oct open: another program creating a Quick Note with `created: 2026-10-14T11:00:00+02:00` adds it to Quick Notes within 2 s; editing Nová stránka dne (its `modified` becomes today) keeps it only in Created; deleting Upravená stránka removes its row within 2 s. The Daily Note's file (when written) never contains section text: after typing, every autosave writes only the user's body and frontmatter, and the file's body equals the editor's body. On a virtual note the sections change and still nothing is written. *(L4; L5; L6 once for the file bytes)*
- **AC-5** **A template may include them as text only.** If the template body contains `## Quick Notes` as plain text, that text is written as the user's content and is not updated by the live sections (FR-DLY-04 "unless the template includes them"; query blocks are v1.0). *(L5)*
- **AC-6** **Limits (D-328).** A section shows at most 50 rows, then `Show <n> more` (plural forms), which shows all in place. With 1,000 generated objects modified on one day the sections paint within 150 ms of `note-ready` (MS4 reports without a target, D-152). *(L5; L6 benchmark)*
- **AC-7** **Keyboard.** Tab reaches each section's rows after the body in visual order; ⏎ opens the row. *(L5)*
