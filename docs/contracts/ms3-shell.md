# MS3 Shell Interface Contract (slice 3A)

- **Status:** draft, 2026-10-12. AP-65…AP-82 accepted as D-121…D-138 (BRD v1.26). The app interfaces the slice 3A acceptance tests use (D-61: tests are written from the ACs and this contract only).
- **ACs:** [docs/acceptance/app-shell.md](../acceptance/app-shell.md). Its reference tables R1 (routes), R2 (right-panel tabs), R3 (disabled controls) and R4 (shortcuts) are the expected registry contents and are not repeated here. Where this contract and the ACs disagree, the ACs win and this contract is corrected before the red tests.
- **Scope:** slice 3A "Frame and page flow" (D-115, D-116, D-120; `docs/plans/ms3-implementation-plan.md` §3, §4). The contract follows D-121…D-138.
- **Builds on** [ms2-shell.md](ms2-shell.md) (launching, test environment, marks, IPC, generated DTOs, automation labels) and [ms2-core.md](ms2-core.md). Everything there stays valid unless this contract changes it.
- **Later slices** add their own sections here: 3B read view (§11), 3C `note_write` and the editor, 3D schema and type settings.

Until a part is implemented it exists as a stub that compiles and returns a deliberately wrong result (an empty list, `null`, `{}` or an `Io` error), so a test fails on its assertion, never on a build or import error (TS-I1).

## 1. Launching and test hooks

Unchanged from ms2-shell §1, plus:

- **Preview build (D-118):** `cd app && npm run app:preview` builds and installs `~/Applications/Tegg Preview.app`, bundle id `app.tegg.preview`, ad-hoc signed, with Application Support root `~/Library/Application Support/Tegg Preview/`. The test build (`app:build`, `app.tegg.desktop`) is unchanged.
- **Minimum window size:** 800 × 500 pt, set on the native window (AP-80, FR-UX-02 AC-18).
- **Test environment** (only with `TEGG_TEST=1`), added in 3A:
  - `TEGG_TEST_PICK_DIR=<dir>`: the folder dialog returns `<dir>` without showing NSOpenPanel; an empty value means the user cancelled (AP-79).
  - `TEGG_THEME=system|light|dark`: start with this theme instead of the stored one, without storing it.
  - `TEGG_ROUTE=<route>`: open this route (§4.1) after the vault opens, instead of the launch landing (§4.3).
- **Marks** (ms2-shell §1):
  - `ui-ready` is redefined: the frame is shown (title bar, sidebar, centre pane, or the chooser when no vault is open) and the palette and the switcher accept input (AP-79).
  - New: `route-ready:<route>` is written once per route per process when that route's page has painted, so Appium waits on navigation instead of sleeping.

## 2. IPC added in 3A

All commands are `async`; errors are `{ kind, message }`. New error kinds: `NotEmpty` (create in a non-empty folder), `NotATeggVault` (open a folder without `.tegg/`, D-91), `Unsupported` (a feature of a later slice, such as a Starter vault before 3D). The UI shows a catalog message per kind and never the `message` text (NFR-OTH-02 AC-2).

| Command | Arguments | Returns | Notes |
| --- | --- | --- | --- |
| `vault_create` | `parent`, `name`, `kind: 'empty' \| 'starter'` | `VaultInfo` | `Vault::create` (ms1-core §3.2), NFC name, then opens it like `vault_open`. Errors `NotEmpty`, `NameTaken`, `Io`; `'starter'` returns `Unsupported` until 3D (D-92). |
| `vault_pick_dir` | — | `string \| null` | Shows the folder dialog (or honours `TEGG_TEST_PICK_DIR`); `null` = cancelled. Replaces the direct `plugin-dialog` call so the test hook has one place. |
| `vault_last` | — | `LastOpenedDto \| null` | The launch landing's note (AP-76): by path if the file exists; else the indexed object with the same `id`; `null` if neither exists or the object is in `.trash/`. Never writes. |
| `vault_types` | — | `TypeDefDto[]` | One per `.tegg/types/*.yml`, NFC keys, read-only; full schema is `tegg-schema` in 3D (AR-07). Order is not guaranteed; the UI orders the list (§3.6). |
| `index_type_counts` | — | `Record<string, number>` | Object count per `type` value of indexed objects, untyped files as `page` (D-103), templates and `.trash/` excluded (FR-TPL-07, D-102). Types with no objects are absent. Types without a definition appear under their raw value (AP-65). |
| `index_list` | `type` | `ObjectRowDto[]` | The objects of one type, same exclusions as the counts, in no particular order (the UI sorts, AP-66, AP-67). |
| `ui_state_get` | — | `UiStateDto` | Machine-local, `<Application Support>/ui-state.json` (FR-STO-07, AP-72). Missing or unreadable file → defaults. |
| `ui_state_set` | `state: UiStateDto` | — | Atomic write of the whole file (temp + rename). Never touches the vault. |
| `nav_opened` | `path` | — | Records an opened note (path and `id`) as the last opened and for switcher recency (D-105). Called by the UI on every note route (AP-82). |

DTOs (Rust structs in the shell, TypeScript generated by `ts-rs` into `app/ui/src/ipc/types.ts`, as in ms2-shell §2):

```ts
type TypeDefDto = {
  key: string;      // file stem of .tegg/types/<key>.yml, NFC: "page", "quick-note", "čajovna"
  name: string;     // "Čajovna"
  plural: string;   // "Čajovny"
  folder: string;   // vault-relative folder
  icon: string;     // icon name from the type file, e.g. "file-text"
  color: string;    // colour name from the type file, e.g. "gray" (mapped to a theme token, §3.5)
  system: boolean;
  invalid: boolean; // the file couldn't be read; name and plural fall back to the key (NFR-REL-03)
};
type ObjectRowDto = { path: string; id: string | null; title: string; type: string; modified: string | null };
type LastOpenedDto = { path: string; id: string | null };
type UiStateDto = {
  version: 1;
  theme: 'system' | 'light' | 'dark';                       // default 'system' (AP-72)
  sidebarOpen: boolean;                                     // default true
  rightPanel: { open: boolean; tab: 'backlinks' | 'outline' | 'graph' };  // default closed, 'backlinks'
};
```

The last-opened record and switcher recency stay in their MS2 store; `ui-state.json` holds only display state.

A type file that changes on disk arrives as `vault:changed` with a path under `.tegg/types/`; any other changed path can change counts. The UI calls `vault_types` and `index_type_counts` again on `vault:changed` (no new event).

Unchanged commands keep their MS2 shape. New object (⌘N) creates through `note_create` with the vault's default type, the same call the switcher's create item makes (AP-75, FR-NAV-01 AC-7).

### 3.3 Commands (FR-UX-03)

```ts
// shell/commands.ts
type Command = {
  id: string;                       // 'goto.inbox', 'goto.type:čajovna', 'object.new', 'view.toggleSidebar', 'theme.dark'
  title: string;                    // catalog key; type commands carry the plural as a variable
  section: 'navigate' | 'create' | 'view' | 'vault' | 'app';
  shortcut?: string;                // one of SHORTCUTS' keys
  due?: Due;                        // set for R3 commands: listed, shown "Coming in …", never run (AP-74)
  needsVault: boolean;              // false only for the commands of AP-81

};
export function commands(ctx: ShellContext): Command[];   // static commands + one per type definition and undefined type value
export function rank(query: string, list: Command[]): Command[];   // folded (case, diacritics, NFC/NFD), letters in order
```

- One key handler, installed once by the shell, runs commands by their shortcut, so a shortcut and its palette entry can't drift (FR-UX-03 AC-7, AC-9).
- **Control-to-command link** (FR-UX-03 AC-8): every button, link, tab, menu item, checkbox, radio and switch in the frame has `data-command="<command id>"`.

### 3.4 Placeholders and disabled controls (D-116, AP-74)

- `shell/Placeholder.tsx` renders a TBD route or tab from its `RouteDef`/`TabDef`: a `region` named by the page name, containing the purpose, `Coming in <due>`, the requirement IDs, and `View design: <board>` or `No design board yet`. It sends no IPC command.
- `ui/Disabled.tsx` wraps a control of R3: `aria-disabled="true"`, focusable, accessible description `Coming in <due>`, shown as a tooltip on hover and focus; activation does nothing.

### 3.5 Themes (FR-UX-05, FR-SET-02)

- `theme/tokens.ts` is the only module with colour literals (plus the logo asset, FR-UX-05 AC-2). It exports `light` and `dark` with the same keys: `bg`, `side`, `panel`, `pop`, `row`, `hover`, `border`, `text`, `muted`, `faint`, `link`, `accent`, `danger`, `focus`, and per type colour `type-<color>` and `type-<color>-bg`. They are applied as CSS custom properties `--<key>` on `:root`.
- The resolved theme is `document.documentElement.dataset.theme` (`light` | `dark`). With `system`, it follows `prefers-color-scheme` live.
- **No flash** (FR-UX-05 AC-6): the shell injects the stored theme into the page before the first paint (an initialization script set from `ui_state` by the Rust side), so the UI doesn't wait for an IPC round trip.
- `theme/contrast.ts` exports `ratio(fg: string, bg: string): number` (WCAG 2.x relative luminance) for the token check (FR-UX-05 AC-3).

### 3.6 Sorting (AP-66)

`i18n/collate.ts`: `collator()` returns an `Intl.Collator` for the macOS region locale, which the shell passes to the page at start (`navigator.language` is the UI language, not the region); `setCollationLocale(locale)` for tests. The Types list order of AP-65 and every name-sorted list use it.

## 11. Slice 3B: read view (D-140…D-151)

ACs: [docs/acceptance/read-view.md](../acceptance/read-view.md) (FR-EDT-10, FR-EDT-02, FR-TYP-08, NFR-PERF-05 AC-2/AC-3, NFR-REL-03 AC-3…5, FR-SYN-03 AC-10/11, FR-SYN-06 AC-6) and its table R5. Where this section and those ACs disagree, the ACs win. Draft, 2026-10-13.

### 11.1 IPC added in 3B

| Command | Arguments | Returns | Notes |
| --- | --- | --- | --- |
| `link_resolve` | `from` (vault path of the note), `targets: string[]` | `LinkTargetDto[]`, same order and length as `targets` | One call per opened note for all its body links, embeds and frontmatter relations (NFR-PERF-05 AC-3). Calls `Core::resolve_links`. Read-only, records no recency. |
| `open_external` | `url` | — | Opens `http:`, `https:` or `mailto:` in the default macOS handler (`tauri-plugin-opener`). Any other scheme returns `Unsupported` and opens nothing; the shell checks the scheme itself, not only the UI (D-145). No network access by the app. |

```ts
type LinkTargetDto = {
  target: string;          // as given (wikilink target without subpath and alias, or decoded Markdown link path)
  kind: 'note' | 'daily' | 'date-missing' | 'unresolved';
  path: string | null;     // vault path (NFC) for 'note' and 'daily'
  title: string | null;    // the target's title (D-73 chip text), null unless resolved
  type: string | null;     // the target's type key, for the type icon
};
```

**Resolution rules** (`Core::resolve_links(from: &str, targets: &[String]) -> Vec<LinkTarget>`, dialect §6, FR-LNK-14):

1. NFC, trim; strip `#…` and `|…` if the UI didn't; compare case-insensitively.
2. A vault path (with or without `.md`), then an `id`, then a file stem. Several files with the stem: the one in the folder of `from`, else the shortest path, then code-point order (dialect §6). This replaces `Index::resolve_link`'s single-stem map for this command; `resolve_link` keeps its MS2 behaviour.
3. Never by title or alias alone (D-141). Never to `_templates/` or `.trash/` (FR-TPL-07, D-102).
4. A target `YYYY-MM-DD` that rule 2 doesn't resolve: `daily` with the path of `Index::daily_note(date)` if one exists, else `date-missing` (D-142, FR-DLY-08).
5. Attachment targets (with a non-`.md` extension) aren't sent: R5 placeholders read nothing (D-144).

`note_read` is unchanged. `Core::read_note` keeps recording recency (§10): 3B has no reads that aren't opens (no previews, D-140; embeds are placeholders, D-144).

Commands the fake core must implement (§5): `link_resolve` by the same rules over its in-memory files, `open_external` recording the URL (`FakeCoreHandle.externalOpened(): Promise<string[]>`) and rejecting other schemes with `Unsupported`.

### 11.2 Routes, shortcut, UI state

- **Search with a tag** (D-143): route `search` takes an optional parameter `tag:<key>` (`search/tag:projekt`, key from `tagKey`); the page opens with that tag filter set and an empty text query.
- **Note subpath** (D-140): route `note/<path>` takes an optional fragment `#<heading text>` or `#^<block id>` (`note/Pages/Cíl.md#Druhá kapitola`); `parseRoute` returns it as `fragment`. The view scrolls to it after `note-ready`.
- **Shortcut** (D-146): R4 gets `⌥⌘U` → command `note.toggleSource` (`Toggle Markdown source`, section `view`, `needsVault: true`). On a route without a note it does nothing.
- **R3/R1 changes** as in read-view.md ("R3 and R1 changes"), made with the 3B implementation (D-150).
- **UI state** (D-147): `UiStateDto` gets `propertiesOpen: boolean` (default `true`, a missing field reads as `true`; `version` stays 1).

### 11.5 Marks and the performance benchmark (NFR-PERF-05 AC-2, D-148)

- `switcher-enter`: written when ⏎ on a switcher result starts a note navigation.
- `note-ready`: written when a note route has painted its formatted view (or source view), all links are resolved, and the title has the focus. Like every mark, at most once per process (ms2-shell §1).
- Benchmark: `app/e2e/perf_open_note.ts` launches the release test build on the reference vault with `TEGG_PERF_LOG` and `TEGG_EXIT_AFTER=note-ready`, opens the switcher, types the target's title, presses ⏎, and records `note-ready − switcher-enter`; 20 launches, p95 < 112 ms. Target note: the generated vault's longest note, with 10 embeds and 50 links added by `tools/gen-vault --perf-note` (a new flag; the seed-1 vault is otherwise unchanged).
