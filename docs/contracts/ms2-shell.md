# MS2 Shell Interface Contract

- **Status:** draft for MS2 (2026-10-12). The desktop app's interfaces that the MS2 app-level acceptance tests use (D-61). Builds on `docs/contracts/ms2-core.md`.
- **Scope:** architecture §12 MS2 "IPC skeleton, shell with main window, progress events"; ACs NFR-PERF-01/AC-1 (cold start), FR-NAV-01 AC-11 ([manual], keyboard switcher), FR-UX-07 progress shown without a modal ([MS3] [manual], partly visible already).
- **Layout** (architecture §11): `app/src-tauri/` (Tauri 2 shell, crate `tegg-app`), `app/ui/` (React + TypeScript, Vite). The shell has its own Cargo manifest (like `tools/`), so the core workspace builds without the web assets.

## 1. Launching

- **Bundle:** `app/src-tauri/target/release/bundle/macos/Tegg.app`, bundle id `app.tegg.desktop`, built by `cd app && npm run app:build`. The executable is `Tegg.app/Contents/MacOS/tegg`.
- **Vault:** the app opens the remembered vault (`Vault::last_opened`, FR-VLT-01 AC-7). With none, it shows an "Open vault folder" button (the full chooser is FR-VLT-01 AC-1, MS3).
- **Test environment** (honoured only when `TEGG_TEST=1`; a release build ignores the other variables otherwise, test-strategy §9):
  - `TEGG_APP_SUPPORT=<dir>`: Application Support root instead of `~/Library/Application Support/Tegg` (FR-STO-07).
  - `TEGG_VAULT=<dir>`: open this vault instead of the remembered one.
  - `TEGG_PERF_LOG=<file>`: append one JSON line per mark: `{"mark": "<name>", "ms": <float>}`, where `ms` is the time since the process started (taken by the OS process start time, so the measurement includes everything before `main`).
  - `TEGG_EXIT_AFTER=<mark>`: quit with exit code 0 right after writing that mark.
  - Each mark is written at most once per process. `TEGG_VAULT` alone opens the vault, also on a first launch with an empty Application Support. `ms` counts from the executable's start (`Tegg.app/Contents/MacOS/tegg`), not from LaunchServices (`open`), whose overhead is part of the MS8 reference-machine check.
- **Marks:**
  - `ui-ready`: the main window shows the vault header and the switcher and search fields accept input. Index state is irrelevant (NFR-PERF-01: "index already built" is the test's precondition, not the mark's).
  - `index-ready`: the first catch-up finished (`IndexProgress` `Done`).

## 2. IPC (architecture §6)

Commands (UI → shell → `tegg-core`), all `async`, errors as `{ kind, message }` (`Conflict`, `Gone`, `NotFound`, `NameTaken`, `Io`, `NoVault`):

| Command | Arguments | Returns |
| --- | --- | --- |
| `vault_current` | — | `VaultInfo \| null` (`{ name, path, placeholders }`) |
| `vault_open` | `path` | `VaultInfo` |
| `index_search` | `query: SearchQueryDto` | `SearchPageDto` |
| `index_switcher` | `q`, `limit` | `SwitcherItemDto[]` |
| `note_read` | `path` | `{ text, version }` (text decoded by `@tegg/doc` rules: UTF-8, BOM kept) |
| `note_create` | `dir`, `title`, `text` (rendered by `@tegg/doc` `newNote`) | `path` |
| `perf_mark` | `name` | — (writes the perf log line; no-op unless enabled) |

Events (shell → UI): `index:progress` `{ done, total, state }`, `vault:changed` `{ paths }`, `note:conflict` `{ path }`.

The DTOs are Rust structs in the shell with TypeScript types generated by `ts-rs` into `app/ui/src/ipc/types.ts` (checked in); `cargo test` in the shell fails when the checked-in file differs from a fresh export (architecture §6, L0).

## 3. Automation hooks

Accessibility labels in the main window (for Appium / the explorer agent): ~~`Quick switcher` (dialog), `Switcher query` (its input)~~ (removed by D-760; the Search page's `Go to` listbox), `Search query`, `Search results`, `Indexing progress`, `Open vault folder`. ⌘O opens the switcher; ↑/↓ move, ⏎ opens, Esc closes (FR-NAV-01 AC-11, FR-UX-03).
