## Bugs

- **G3.** Every type picker and suggestion list calls `typeIconName(key)` without the type's `icon`, so a user type falls
  back to the generic `type` glyph: the capture type pill and menu, `[[` / `@` suggestions (editor and relation
  fields), the embed picker and the conversion popover. The sidebar, tabs and chips pass the icon and are right. Fix: one
  helper that looks the type up and passes `icon` (and its colour where the list shows one). Test:
  `bug_ms5b2_fr_typ_06_user_type_icons` (L5: a user type with `icon: lightbulb` shows that icon in each list).
- **G6.** Reproduced with the fake core (WebKit): (1) column alignments are dropped: `:---:` and `---:` columns are left
  aligned, and header cells are centred by the browser's default; (2) a wide table is squeezed into the page width, so
  words break mid-word (`c1` / `0`) and cells clip, instead of keeping its width and scrolling sideways as the read view
  does (`.table-wrap`). Fix: the editor's table node keeps `align` per cell, headers are left aligned unless aligned,
  and the table sits in a horizontal scroller. Test: `bug_ms5b2_fr_edt_02_table_alignment_and_width` (L5). **Owner:** if
  what you saw is something else (a table shown as raw text, a broken row), send the table's Markdown (synthetic).
