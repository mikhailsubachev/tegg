# Feedback on 0.4.0: views on type pages (slice Q2)

Owner, 2026-11-19, on the installed Tegg 0.4.0 (PR #145). The follow-up slice is **Q2.1**, released together as **0.4.1** before Q2-T (D-1837, D-1878).

## F1 · The view menu opens outside the window (bug)

The toolbar `⋯` (`View actions`) on a view tab opens its menu past the window's right edge: `Edit view` and the other items are cut off. A menu must stay inside the window (open leftwards or upwards when there is no room, clamped to the edges). This is a bug fix: a failing regression test first (`bug_q21_fr_qry_07_view_menu_stays_in_the_window`), no decision needed.

## F2 · Trashing a view keeps its tab

`Move to trash` in a view's menu moves the query to `.trash/` but leaves the tab on the type page, showing `in the trash` with `Restore` (as specified by D-1435 and FR-QRY-07 AC-11). The owner expects the view to be gone from the page.

**Decision D-1835:** `Move to trash` from a view's menu also removes the tab: it writes `views:` without the name and moves the query file to `.trash/`, with one Undo (8 s) that restores both. Notes that embed the query keep D-1435's `in the trash` state with `Restore`. A query trashed outside Tegg (or from the Queries page) while still listed in `views:` keeps the trashed tab, as now. Amends D-1435 for views and FR-QRY-07 AC-11.

## F3 · Sort, columns and widths per usage

When one view is shown both as a tab on a type page and as a block in a note, the tab has much more room. Sorting, the chosen columns and the column widths must be set **per usage instance**, not shared through the query.

**Decision D-1836:**
- Each usage keeps its own **sort** and **columns**, in the vault: a block in its fence in the note (` ```query ` with `saved: <name>` plus its own `sort:` / `columns:`), a tab in the type file's `views:` entry for that view.
- Each usage keeps its own **column widths** on this Mac (`ui-state.json`), keyed by the usage (the tab of a type page, or the block in a note).
- The query file's `sort` and `columns` are the **defaults** for a usage that has none of its own; filters, `group_by`, `lanes` and `lane_order` stay shared by every usage.
- Amends D-1444 and D-1766 (a header click or the sort popover writes the usage, not the query file), D-1437 (`columns` per usage), D-1767 (widths per usage, not per query). The exact shapes in the fence and in `views:`, how a usage goes back to the query's default, and what Duplicate and rename do with usage settings are open points for the ACs (AP-1519 onward).

## F4 · Release

**Decision D-1837:** F1…F3 ship together as slice Q2.1; Q2-T follows. **Changed by D-1878** (owner, 2026-11-20): released as **0.4.1**, not 0.5.0.
