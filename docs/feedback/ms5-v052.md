## Bugs

- **H1a, H15 (the Embeds section of Type settings).** `Full · Card · Link` are `role="radio"` spans with the class
  `ts-radio`, but no rule styles `.ts-radio`: they render as three plain words, the checked one looks like the others,
  there is no pointer cursor, and a click changes nothing you can see (the file is written). This is what "not
  clickable" and "setting the type does not work" describe. Fix: the segmented-control look of the other Type settings
  choices, the checked one filled, `cursor: pointer`. Test: `bug_v052_fr_emb_02_type_settings_embed_mode_is_a_control`.
- **H1b (a link-mode block embed).** Choosing `Link` in an embed's `Display as` turns it into a chip without a
  `Display as` button, and `Display embed as…` on the selected block does nothing (it clicks a button that isn't
  there), so the mode can't be changed back except in the source view. D-428 says `Display embed as…` opens the mode
  menu on a selected block embed. Fix: D-598. Test: `bug_v052_fr_emb_02_link_mode_block_embed_keeps_display_as`.
- **H6.** The capture text is a transparent textarea over a mirror that draws the title line at weight 650 (D-592).
  The caret and selection come from the textarea's 400-weight glyphs, so on a long title they drift away from the bold
  text shown. Fix: the mirror draws the title bold with a text stroke at the textarea's weight, so every glyph keeps its
  width. Test: `bug_v052_fr_cap_01_caret_matches_the_bold_title`.
- **H9, H10.** The watcher reports Tegg's own saves (`vault:changed` for the note). The note page compares the file
  with `diskTextRef`, which is only updated on the next React render after a save, and not at all while a save is on
  its way. So an own save seen in that window is taken as an external change: with edits typed since, the merge dialog
  opens (H9); without, the editor reloads the note and the caret jumps (H10). Fix: the saver records the text it is
  writing and the last text it wrote, and `diskTextRef` is set when the save returns; a change whose bytes are one of
  these is the note's own write (no reload, no dialog; the version is taken as the new base). A real external change
  still reloads or merges as before. No autosave delay is added. Test:
  `bug_v052_fr_syn_03_own_save_is_not_an_external_change` (L5: the fake core reports each write as a change, during and
  after the write).
- **H13.** Search results and the quick switcher still use the 3B emoji map (`📄`, `◆` for every user type). Fix: the
  type's icon, as in the sidebar and chips (D-236, D-519). Test: `bug_v052_fr_src_03_type_icons_in_search`.
