# Feedback on 0.4.1 for slice Q2-T

Owner, 2026-11-20, when starting slice Q2-T (Tasks on saved queries, `docs/plans/q2-views-plan.md` §7). These points ship in Q2-T, released as **0.5.0**.

## F1 · Wide pages get a maximum width

On ultra-wide monitors a wide page (D-1772: a type page with its views, the Queries page, a query page) stretches across the whole screen.

**Decision D-1890:** a wide page fills the main pane up to **1600 px** and is centred beyond that. A board or table wider than that still scrolls sideways inside it. Notes keep their own widths (`.note-column`, slice PW). Amends D-1772.

## F2 · Board cards follow the type's card setup

**Decision D-1891:** a card on a board shows the attributes of **its own type's Preview properties** (Type settings › Preview properties, the type file's `preview:` key; the same setup as embed cards and previews, D-1240). A board that shows several types shows each card per its type. The view's own `On cards` (`columns` on a board) goes away: no `On cards` row in the query editor and no `Change…` on a board. A `columns` key on a board query is kept in the file and ignored. Amends D-1793 (which attributes a card shows), D-1844, D-1860 and D-1884 (`On cards` per usage). How the card lays out the attributes (pills, footer chips, `#tags`, two body lines) stays as D-1793. Open points for the ACs: what happens to existing board files with `columns`, and the Task card on the Tasks Kanban (D-74's checkbox, status, priority and due).

## F3 · A card in two lanes shows its links in red (bug)

On a board grouped by a multi-value relation, a card that sits in two lanes shows the grouping attribute's link chips in red, as unresolved links, although both targets exist. A bug fix: a failing regression test first (`bug_q2t_fr_qry_07_multi_lane_card_links_resolve`), no decision needed.

## F4 · Multi-level sort and the tag filter on every view

**Decision D-1892:** every view of every type, the Tasks views (Schedule, Kanban, …) included, offers the multi-level sort (D-1766) and the searchable tag filter of today's Tasks page (not saved, D-1779), so that all views behave like the other table views. The details (where the tag filter is kept, blocks in notes, sorting inside lanes) are open points for the ACs.

Details decided by the owner the same day:
- **D-1893:** a tab's tag filter is kept on this Mac per tab, across leaving the page and relaunching.
- **D-1894:** query blocks in notes don't get the tag filter.
- **D-1895:** on a board and on Schedule the sort orders the cards within each lane, every lane alike, the done lane included.
